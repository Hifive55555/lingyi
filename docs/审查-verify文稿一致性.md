审查对象

| 文件 | 规模 |
|---|---|
| `paper/verify/main.typ` | 85 行（含摘要与两个附录） |
| `paper/verify/sections/01–08.typ` | 475 行 |

| 编译产物 | 20 页，`typst compile --root .. main.typ` 通过，无 error（仅 `simsun` 缺字体 warning） |

方法：逐节读原文 → 每条数值回查 `paper/shared/data/*.csv` → 每条图注回查 `paper/shared/{figures,schematics}/*` 的实际文字层 → 标签/引用做全量配对 → 与 `STYLE.md` 的硬性条款比对 → 与 `paper/design/` 对照跨稿冲突 → 编译后从 PDF 抽取"图 N / 表 N"实际编号，核对文内指代。

**总体**：结构与四段式（设计 → 应用 → 实机核对 → 关键数据）执行得很好，诚实度也高（明确写"不可判定"）。问题集中在三类：**附录 A 的界面清单与截屏不符**、**图号/样本量/ε 级数字的陈旧与互斥**、**四节图序与 `STYLE.md` 相反且大量图从未被正文引用**。

## 一、阻断级（评审可直接核对，必须先改）

### 1.1 附录 A「界面操作路径」与本文自己用的截屏不符

附录 A 声称"本报告所有与界面有关的描述都可以在客户端里复现""全部为界面可读信息"，列出 8 项入口：`战况 / 指令列表 / 得分 / 导出态势 / 数据查看 / 红方视角 / 战役复盘 / 智能体调度`。

但本文所用的实机截屏（`fig_evidence-1.png`、`fig_verify-timeline` 的六帧、`fig_apply-*`）里，工具条只有 **7 项**，逐字为：

```
数据查看 | 想定描述 | 简报 | 条令规则 | 实时得分 | 卫星临空 | 战前部署
```

即：`战况`、`指令列表`、`导出态势`、`红方视角`、`战役复盘` 五项在图上一个都找不到；`得分` 疑对应 `实时得分`；`数据查看` 一致。顶部菜单（推演 / 任务 / 智能体调度 / 视图 / 标绘 / 重置 / 帮助）与附录一致。

后果不止于表格本身：**§8.3 的复核条件完全建立在这批按钮存在的前提上**——"打开三个面板重录：战况、指令列表、得分……这三个按钮已在客户端工具条上，不需要平台改动"。其中两个按钮在本文证据里不存在，整条建议的可行性未获证明。

改法二选一：
- 若这些面板确在别处（例如推演未开始时的规划界面，或右侧折叠面板），补一张能读出这些按钮的截屏并注明位置；
- 否则把附录 A 改成"截屏可读的 7 项"，把 `战况/指令列表/导出态势` 标为"存在性待回查"，并把 §8.3 的措辞从"按钮已在工具条上"改成"需先确认入口"。

### 1.4 端到端表的两个 `d0` 算错（且与自家 CSV 冲突）

## 四、与 `STYLE.md` 的偏离

### 4.1 图序与规范相反（4/4 节全部如此）

`STYLE.md` 规定每节图的顺序为 **示意图 → 数据图 → 实机截屏**。实际：

| 节 | 实际顺序 | 规范要求 |
|---|---|---|
| 3 空战躲避 | 图4 示意 → **图5 实机** → 图6 数据 → 图7 数据 | 示意 → 数据 → 实机 |
| 4 空空交战 | 图8 示意 → **图9 实机** → 图10 数据 | 同上 |
| 5 船只自卫 | 图11 示意 → **图12 实机** → 表5 → 图13 数据 | 同上 |
| 6 地空导弹营 | 图14 示意 → **图15 实机** → 图16 数据 | 同上 |

连带后果：**标签顺序与出现顺序不一致**——`eva-4 < eva-2`、`acm-3 < acm-2`、`shp-3 < shp-2`、`sam-3 < sam-2` 全部倒挂。日后插删图极易错位。

两条路：改文稿（把"关键数据"提到"实机核对"前），或改 `STYLE.md`（承认"实机核对"前置是对的）。从阅读逻辑看，后者更合理——先证明"看到什么"，再给"仿真支撑什么"；但必须同步改规范，否则下一次写作又会踩。

### 4.2 18 个标签从未被正文引用

未被 `@` 引用过的标签：`fig:ov-1`、`tab:ov-1`、`fig:ov-2`、`tab:ov-2`、`sec:monitor`、`fig:mon-1`、`fig:eva-1`、`fig:acm-1`、`fig:shp-1`、`fig:shp-2`、`sec:sam`、`fig:sam-1`、`fig:syn-1`、`fig:syn-3`、`fig:syn-4`、`tab:ccl-1`、`tab:ccl-2`、`fig:ccl-1`。

其中**五张示意图（mon-1 / eva-1 / acm-1 / shp-1 / sam-1）一张都没被正文引用**——`STYLE.md` 写"正文用 `@fig:xxx` 引用"，现在读者读完一段设计文字，看不到"请看图 4"的指针，只能自己去找。这也是 `tab:ccl-1` 图号会陈旧到无人发现的直接原因：反正没人引用。

建议：每节"设计"段末尾补一句 `@fig:eva-1 给出…`，`tab:ccl-1` 的"证据"列改用 `@fig:`。

### 4.3 `d0` 被完整定义两次

`STYLE.md`：不要重复其他章节已给的定义（`$d_0$`、证据分级等），用一句话引用即可。
实际：`02-monitor.typ:32-40` 完整推导一遍并给 42.7 km 的算例；`04-aircombat.typ:53` 又写一遍公式与同一算例。监控一节本来没有数据，为了凑"关键数据"而借用了 d0——这才是根因：**02 的"关键数据"段其实不属于监控**。

建议：把 02 的关键数据改成"本智能体无独立指标；其两个输出字段的价值由 03/04 的判据间接体现"，d0 只在 04 定义一次。

### 4.4 `fig:syn-4` 是表却用 fig 标签

`07-scenario.typ` 的端到端块是 `#figure(kind: table, ...) <fig:syn-4>`，PDF 里编为 **表 7**。标签叫 `fig:` 但显示为"表"，交叉引用会写成"图 syn-4"，语义错位。改为 `tab:syn-1`。

### 4.5 术语表两处不严谨

- **`D_max`**：附录 B 只写"防空导弹最远射程；地空导弹营语境下由模型二分求得 100.8 km"。而 05 用 `D_max = 60 km`（舰空弹）。同一个符号两个值、术语表只覆盖一个。建议拆成 `D_max^SAM = 100.8 km`（地导）与 `D_max^ship = 60 km`（舰空），或在术语表加一句"两处取值不同：舰空 60 km，地导 100.8 km"。
- **巡逻区"共七类"**：括号里列了 `阵风 1/2、TB1/TB2/TB3、S70-1/2、左制空/北制空` = **9 个编号**，与"七类"矛盾。而图内标注写的是"巡逻区（阵风 **2**，另有 TB1/2/3、S70-1/2、左制空）"= 7 个（不含阵风 1、不含北制空）。以图为准，术语表括号内容应改成与图注一致。

### 4.6 篇幅偏离

`STYLE.md`：每节 1.5–2.5 页，总览与结论各 1 页。按 PDF 实际页码（从标题字号定位）：

| 节 | 页 | 实际篇幅 | 规范 |
|---|---|---|---|
| 1 总览 | 1–3 | ≈ 2.2 | 1 页（超） |
| 2 监控 | 3–5 | ≈ 1.7 | ✓ |
| 3 空战躲避 | 5–8 | **≈ 3.2** | 上限 2.5（超） |
| 4 空空交战 | 8–10 | ≈ 2.1 | ✓ |
| 5 船只自卫 | 10–13 | ≈ 2.6 | 略超 |
| 6 地空导弹营 | 13–15 | ≈ 1.8 | ✓ |
| 7 综合运用 | 15–18 | ≈ 2.6 | 略超 |
| 8 结论 | 18–19 | ≈ 1.5 | 1 页（超） |

3 节装了 4 张图 3 张表（含整张 `tab:eva-1` 与敏感性图），是最该拆的一节。另外 `fig6-sensitivity` 在 3 节与 7 节各出现一次（图 7 与图 18 是同一张图），虽为 `STYLE.md` 的分配表所允许，但两处都在说“过载悬崖”这一件事，合并后两节都能落回区间。
