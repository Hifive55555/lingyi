# 架构与数据流

> 读这份能回答三个问题：**谁在跑、数据怎么流、出问题看哪个日志。**
> 硬约束（不许违反的规则）在仓库根 `AGENTS.md`，这里只讲结构与事实。

## 1. 三个组件

```
┌──────────────────────────────────────────────────────────────────────┐
│ 灵弈引擎进程（APlatform / 推演进程，ray210 python 3.9）              │
│                                                                      │
│   Mission_all_red.py / Mission_all_blue_hh.py   ← 规则智能体         │
│     initial(situation)  战前规划：条令/WRA/任务/战前移动/BOL         │
│     step(situation)     每决策周期（10 s 仿真时间）下指令            │
│                                                                      │
│   overlay.agent.OverlayAgent  ← overlay_ai.py 里 class Agent 继承它   │
│     · 与规则智能体在**同一个进程**里，读同一份态势                    │
│     · 起 WebSocket 服务 127.0.0.1:8760/ws，把快照推给小窗            │
│     · 接收小窗下发的指令（武器分配/油门/高度/条令），转给引擎         │
│                                                                      │
│   BattlefieldMonitor / SamBattalionDefense / ShipClusterDefense       │
│     ← 被规则智能体 import 的三个战术模块（纯计算 + 少量状态文件）      │
└──────────────────────────────────────────────────────────────────────┘
        ▲ 8760/ws 快照 + 指令
        │
┌───────┴──────────────────────────────────────────────────────────────┐
│ launcher.py（独立进程，双击 灵弈小窗.bat 或桌面快捷方式）             │
│   · aiohttp 页面服务 127.0.0.1:8761  提供 web/*.html|js               │
│   · 拉起 wv2\overlay_wv2.exe 两个窗口（自带 WebView2，不用 Edge）      │
│       主小窗   灵弈小窗   页面 480×860   贴屏幕右侧                   │
│       监控小窗 监控小窗   页面 1100×620  紧贴主小窗左侧                │
│   · 按 PID 认窗口、置顶、尺寸记忆（wv2_size_<标题>.txt）               │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么小窗要单独进程**：引擎进程是全屏推演，没法在里面开 GUI；
小窗只读态势、发指令，崩了不影响推演（`_mon_block` / `_sam_rows` 全部 try/except）。

**为什么两个窗口同源**：监控窗不单独连端口，读的是同一个 ws 快照里的 `mon` 字段
（早先的 `monitor-agent` 独立包已合并进来，8762/8763 端口**不再使用**）。

## 2. 端口与环境变量

| 端口 | 谁监听 | 用途 |
| --- | --- | --- |
| `8760` | 引擎进程里的 `OverlayServer`（aiohttp） | `ws://127.0.0.1:8760/ws` 快照下发 + 指令上行 |
| `8761` | `launcher.py`（aiohttp） | `http://127.0.0.1:8761/` 页面（`web/overlay.html`、`web/monitor.html`） |

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `LY_OVERLAY_PORT` | `8760` | ws 端口（agent 侧） |
| `LY_OVERLAY_PAGE_PORT` | `8761` | 页面端口（launcher 侧） |
| `LY_PYTHON` | 空 | 指定 python.exe（非标准安装路径时用） |
| `LY_OVERLAY_SIDE` | `蓝方` | 本地测试用阵营 |
| `LY_OVERLAY_UDF` | 空 → exe 同级 | WebView2 用户数据目录；**不要指到 `%LOCALAPPDATA%`** |
| `LY_OVERLAY_NO_BROWSER` | 空 | `1` = 只跑页面服务，不拉窗口（调试页面用） |
| `LY_OVERLAY_NO_MONITOR` | 空 | `1` = 只开主小窗，不开监控窗 |
| `LY_OVERLAY_PROFILE` / `LY_OVERLAY_APP` | 空 | 仅 `msedge --app` 兜底路径使用 |
| `LY_SAM_STATE_DIR` | `%LOCALAPPDATA%\LingYiOverlay` | 战术模块与小窗交换状态的目录（可写才有效） |

## 3. WebSocket 协议

**下行（服务端 → 客户端）**，每决策周期一条，空闲时每 3 s 一条心跳：

```jsonc
{"type": "snap", "t": 3725, "side": "蓝方", "started": true,
 "units":   [ /* 我方单元，见下 */ ],
 "contacts":[ {"id":"…","n":"…","ty":4,"lat":0.0,"lon":0.0,"ms":true} ],   // ms=是否导弹
 "sam":     [ {"id":"…","n":"…","role":"sam|radar","dir":"…","mode":"auto|manual"} ],
 "notes":   ["最近 6 条提示"],
 "mon": {   // 监控窗（被攻击监控）
   "t":3725, "side":"蓝方", "started":true, "cycle":41, "ms":9, "own":7,
   "groups": {"air":[2,3], "sea":[1,2], "land":[1,2], "all":[4,7]},   // [被攻击数, 总数]
   "rows": [ {"n":"苏35 #12","g":"air","alt":10200,"spd":900,"dmg":0,
              "hit":true,"n_ms":3,
              "ms":[ {"n":"48N6E2[远程]","db":…,"spd":3600,
                      "d":126.4,"cpa":12.5,"tgo":48} ]} ],
   "cfg": {"gate":null,"sec":10}
 }}
{"type": "hb"}
```

`mon.rows[].ms[]` 的语义（**容易误读**）：

- `d` = 当前距离（km），`cpa` = 最近接近点距离（km），`tgo` = 到**最近接近点**的时间（s）
- `tgo` **不是命中时间**：一枚 562 km 外横向掠过的弹，`cpa≈562 km`、`tgo` 可能只有 16 s
- `tgo == null` → 还算不出来（刚出现/数据不全），页面显示 `—`（灰色左边框）
- `cpa > d*0.5` → 判定为「擦边掠过」，页面压暗并在 tooltip 说明

**上行（客户端 → 服务端）**：

```jsonc
{"type":"cmd", "req":"<动作名>", "cid":"<客户端生成，去重用>", …参数}
```

服务端回 `{"type":"ack","req":"…", "ok":true, "msg":"…"}`；
同一 `cid` 重复发送会命中缓存（`OverlayServer.done`，上限 500 条），
所以页面点两下不会重复下发。

```jsonc
{"<想定id>": {"<阵营id>": {"<智能体名>": {"id":"…", "className":"Agent",
                                          "filePath":"D:/灵弈/intelligent/ai/agent/Mission_all_red.py"}}}}
```

## 5. 日志与排障入口

| 文件 | 内容 | 什么时候看 |
| --- | --- | --- |
| `…\ai\agent\overlay\logs\launcher.log` | 页面服务、窗口拉起、端口占用 | 小窗没起来 / 灰屏 |
| `…\overlay\logs\agent.log` | 引擎内 `OverlayAgent`：ws 监听、指令下发、异常 | 小窗连不上 / 指令没反应 |
| `…\overlay\logs\boot.log` | 导入链（每步一行）、`sys.path`、`Agent.__init__` | `ModuleNotFoundError` / 启动就挂 |
| `…\overlay\logs\crash.log` | faulthandler 栈 | 进程直接消失 |
| `…\overlay\wv2\wv2_err.log` | WebView2 宿主：`CreateAsync udf=…`、`nav ok=…`、`FAIL …0x80070005 / 0x800700AA` | 小窗白屏/灰屏 |
| `…\overlay\wv2\wv2_size_<标题>.txt` | 关窗时记下的窗口尺寸（宽,高-26） | 窗口大小不对（删掉即回默认） |
| `…\ai\config\<智能体名>\log\command_delay.log` | 平台侧：技能加载、`Apply - ERROR`、指令耗时 | 智能体「运行异常」 |
| `<灵弈>\Logs\` | 平台自身日志 | 推演层面问题 |

常见错误码对照在 `AGENTS.md` §4。

## 6. 一次决策周期的时序

```
t=N       引擎调用 Agent.step(situation)
            ├─ 规则智能体：维护任务/条令，按需下指令
            └─ OverlayAgent：_build(t) → 快照（units/contacts/sam/mon）
                        ↓ 8760/ws
          页面（小窗）渲染：主小窗列表/详情，监控窗三列（空|海|陆）
                        ↑ 用户点按钮 → {"type":"cmd",…}
          引擎执行指令（可能触发 _OrderBudget 限流：任意 10 s ≤ 460 条）
t=N+10s   下一周期；监控窗按 `mon.rows[].ms[]` 重画（固定排序，不随 tgo 抖动）
```

指令限流在 `Mission_all_*.py` 的 `_OrderBudget` 里：它包住平台的 `_game_server`，
按「任意 10 秒 ≤ 460 条」做真·滚动窗口节流（平台硬上限 500 条/10 s，
超了会静默丢包）。**这条不能删**：删了会在开局大批量下发时随机丢指令。
