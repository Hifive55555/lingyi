# 04 · 代码结构映射：实际智能体代码 → 讲解里的五个智能体

> 目的：用 grep/read 实读代码，把「实际代码」的结构、函数、阈值全部落到行号，再映射到讲解（`docs/讲解/01-手写笔记转写.md`）的五个智能体：**监控 / 地空导弹营 / 空战躲避（飞机躲避）/ 船只自卫 / 打空战**。
>
> 结论先行（详见第 3 节）：
> - **「空战躲避」「打空战」两件事在代码里确有实现**（`agent6_fighter.py` / `agent6_fighter_blue.py` + 两份 `calculate_*.py` 依赖文件），但**阈值与讲解不一致**（60km vs 50km、`MIN` vs 305m、固定 WRA 距离 vs d0 追击模型）。
> - **「监控」「地空导弹营」「船只自卫」在代码里没有对应实现**，最接近的只是"条令设置 / 任务分配 / 火力规则"级别的等价物，映射全部标【推测】。
> - 两个"最新实际代码"主文件 `Mission_all_red.py` / `Mission_all_blue_hh.py` **不是**五个战术智能体，而是**部署型（一次性）规则智能体**：总条令 + 挂载 + 任务 + 航线 + BOL 打击，`step()` 里没有空战/规避/拦截逻辑（`[RED]` 2774-2811、`[BLUE]` 1817-1912）。
> - 该目录 `README.md` 明确写着："这是实际运行于灵弈的实际智能体，但最终的报告不参考实际的实现，最终的智能体报告遵从[智能体讲解]的说法。本代码的作用是提供灵弈系统的结构示例。" —— 因此本文的定位是**给报告提供结构示例 + 核对阈值的证据**，不是给报告背书。

### 1.2 怎么被平台调用（依据 readme.txt 与代码）

1. **导入路径**：平台把 `<安装目录>\intelligent\ai` 加入 `sys.path`，智能体按 `engine.LingYi.entitys.*` 导入（`[RED]:35-40`、`[BLUE]:24-31` 注释：放在 `intelligent\ai\engine\LingYi\` 下即可）。客户端导入步骤：`[RED]:42-44`、`[BLUE]:33-35`——推演方选阵营 → 导入/选择脚本 → 勾选"规则智能体" → 开始推演。
2. **两个必需回调**：文档 `docs/资料/_pdf/联合作战人机协同博弈挑战赛智能体开发与应用指南V1.1.md:148-150` 写明——推演开始前调用一次 `initial`，之后每到决策间隔（`get_server_config` 里配置）调用一次 `step`。
   - `[RED]:2699` / `[BLUE]:1718` 的 docstring 都写"每局推演开始前调用一次（战前规划阶段）"；`step` 的 docstring 写"每个决策间隔（默认 30 秒仿真时间）调用一次"（`[RED]:2775-2776`、`[BLUE]:1818-1819`）。
   - `deduction_end()`（`[RED]:2812`、`[BLUE]:1913`）是推演结束回调，两份代码只用来打统计日志。
3. **继承哪个基类**：主文件用 `class Agent(RuleAgentBase)`（`[RED]:273`、`[BLUE]:253`），样例1/2 全部用 `class Agent(Player)`（如 `[R1]:18`、`[S2-条令]:8`）。指南 `:382` 说"可继承 `RuleAgentBase` 编写规则智能体"，样例代码里同时 `import RuleAgentBase`（`[R3]:6`）却实际继承 `Player` —— 两种写法在样例里并存。
4. **单文件 vs 多文件**：
   - 样例1 是**多文件**：`红方智能体/readme.txt` 只有三行——"`退退退不掉队_红方.json` 为配置文件 / `rule_agent` 保存有所有智能体 / `fighter` 中 `calculate...py` 文件为依赖文件"；`蓝方智能体/readme.txt`："`rule_agent` 文件夹为蓝方的所有智能体代码，请将该文件夹放至 `LingYi\intelligent\ai\agent` 中。`退退退不掉队-蓝方配置.json` 为配置文件。"
   - 配置文件确实逐文件挂载：`红方.json:4-70` 里 7 个 key（`agent1_add_mission#1` … `agent7_AutoAttack#1`），每个都带 `filePath`（如 `:59` `"red/fighter/agent6_fighter.py"`）与空 `unit` 字典；`蓝方配置.json:4-70` 同构（`:59` `"rule_agent/air_combat/agent6_fighter_blue.py"`）。指南 `:367-371` 解释这套键值：`unit` 字典 = 该智能体控制的己方单元名。
   - 主文件是**单文件**：红/蓝各只有一个 `Agent` 类，整方所有动作都由它下发（`[RED]:6-36`、`[BLUE]:5-22` 的 ①~⑨/①~⑥ 清单即证据）。
5. **指令条数限制**（两份主文件共同的工程约束）：平台启动参数 `agentOrderCountLimit = 500`，按"任意 10 秒 ≤ 500 条"计（`[RED]:52-56`、`[BLUE]:51-54`）；两份代码都包了 `_OrderBudget` 做滚动窗口节流（`[RED]:102-210`、`[BLUE]:89-193`），并把 `_game_server` 重绑到计数器上（`[RED]:2626-2667`、`[BLUE]:1651-1692`）。
