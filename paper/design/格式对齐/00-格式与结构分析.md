## 1 模板是什么

`智能体设计报告模板.pdf` 不是空白模板，而是**赛会提供的样板报告**（ref.bib 中 `samplereport2026`「智能体设计报告（赛会样板）」）。它给出的是"一份合格报告的版式 + 章节骨架"，内容属于另一支队伍（尤卡坦/诺曼底想定、红蓝双方 8 个智能体）。

因此"完全参考模板"应当理解为：**照抄它的版式参数与章节层级惯例，不照抄它的内容，也不照抄它的排版错误**（模板自身有瑕疵，见 §7）。

       2.4.1 基础智能体     ← 时间复杂度 O(n)、下发频率限制

**模板的写法惯例**（比版式更值得注意）：

1. 每个智能体一节，节内固定顺序：**规则说明 → 示意图 → 伪代码 → 定量/性能**。
2. 每章主体都是"正面陈述 + 数据支撑"，没有对照组、没有消融、没有"我们的规则不成立"这类结论。
3. 交叉引用全部用**相对方位词**（"如下图""下表""如前所述"），因此才可以不编图号表号。
4. 数字都写成"提升约 40%""减少 90% 以上"这类**效果口径**，不是实验口径（无样本量、无随机种子）。

## 2 我们现有文档的现状

`paper/design/润色后/main.typ`：easy-paper 0.2.2 模板，A4，29 页，1 篇摘要 + 12 章 + 3 附录 + 参考文献（GB/T 7714，11 条）。18 张图、13 张表、31 个 `#figure()`、36 处 `@fig:/@tab:` 交叉引用、13 处 `@sec:` 引用、**14 处硬编码"第 N 章"**、1 处"第 4.2 节"。

```
引言 → 总体架构 → 临界距离闭式解 → 空战单元自卫 → 空空作战
→ 登陆船只集群自卫 → 地空导弹营 → 参数与模型形式稳健性
→ 端到端对比 → 应用效果 → 局限与未来方向 → 结论
附录 A 仿真参数总表 / 附录 B 重现方法 / 附录 C 术语与型号对照表
```

与模板最大的差异不是排版，而是**叙事类型**：模板是"我们做了什么、效果多好"的工程汇报；我们是"每个阈值凭什么这样取、改成什么更好、在什么前提下不成立"的方法论报告。这决定了映射时不能用模板的章节名硬套我们的内容（详见 §5）。

## 4 模板有、我们没有 —— 缺口清单

> 这一节是本次分析的重点：模板里出现而原文完全没有的内容，逐项给出"能不能补、从哪补、风险多大"。

### 4.1 §1.1 想定分析与博弈论建模 —— 缺，可部分补
模板内容：想定态势解读 → 定性为双人零和博弈 → 定义策略集/资源集（红 52 单元、蓝 60 单元）→ 写效用函数 $U_r$（交战收益 + 保全收益 − 敌方保全损失）→ 纳什均衡/极大极小 → 红蓝六类作战域分值对比表 → 双方最优策略 4 条。
我们的现状：**完全没有**。附录 C 术语表有 ABDE 区、雷鸣号、海马斯等想定名词，`docs/资料/03-系统接口与想定.md` 与`诺曼底2027想定说明.md` 有想定数据。
可补程度：想定态势与双方兵力/分值对比表 → 可依据想定说明补写，**工作量中等，风险低**。零和博弈模型与效用函数 → 属于新写的理论包装，与全文"阈值审计"主线关联弱，**建议补但压缩为 1 页**（只保留零和判断 + 分值表 + 结论"红蓝最优策略"），不做效用函数推导，避免与第 1.4 节的方法论主线打架。

### 4.2 §1.2 人机协同必要性 —— 缺，可改写
模板：三点（算法补人类实时操作短板 / "人类管战略、算法管执行"分层 / 经验与效率互补）。
我们有素材：引言"它们不负责替指挥员定下决心，只接管连续、机械、时间敏感的执行环节"、第 2 章"调用周期/可观测性/动作约束"。
**工作量小，风险低**。

### 4.3 §1.3 红蓝双方人机协同系统架构表 —— 缺
模板：红、蓝各一张四行表（架构维度 / 核心内容 / 对应代码·操作支撑），是本报告唯一的"分工落地"证据。
我们的现状：只有一张架构图 + 一张最小规则集表，且**只覆盖我方一侧**（红方/登陆方）；文中明确写"四个下游智能体互不相交"。
风险：蓝方智能体我们并未逐条审计，若照模板补"蓝方架构表"，等于新增未验证内容。**建议只做红方一张，并在文中说明"本报告审计范围为红方五智能体；蓝方同构，不复述"**。

### 4.4 §2.2 基础智能体三件套（任务部署 / 条令设置 / 武器挂载）—— 缺
模板 2.2 占 12 页（p9–p20），是篇幅最大的一节，内容为任务大纲大表 + 三战区逐区战术分析 + 伪代码图。
我们的现状：**一个都没有**。我们的"基础智能体"是物理作战域三维监控（信息底座，不是战前规划）。`文档/智能体样例1/红方智能体/` 里有 `agent1_add_mission.py / agent2_radical_agent_doctrine_set.py / agent4_red_loadout_set.py`，是平台样例代码，不是我们的实现。
结论：**不能补，也不应补**。若强行套用模板目录，会出现"有章无文"。处理方式见 §5.1 的方案 B。

### 4.5 §2.3.1/2.3.3/2.3.4/2.3.5 加油规划 / 预警机 / 自动打击 / 任务区动态规划 —— 缺
同上，完全没有对应内容。模板 2.3.2 战斗机智能体里的"两阶段规避（之字形）"与我们的 2.3.1 空战单元自卫部分重叠，是唯一可类比的点（我们的分析更深，但结论相反：纯运动学下垂直扭动负收益）。

### 4.6 §2.4 性能分析（时间复杂度 / 决策耗时 / 排队论）—— 部分缺
模板给出：`O(n)`、`O(n²)`、200 单元 45 ms、100 单元 25 ms、M/M/c 排队指标、算法对比雷达图与收敛曲线。
我们的现状：有蒙特卡洛效果曲线、敏感性龙卷风图、稳健性扫描，**但没有时间复杂度、没有单步决策耗时**。
可补程度：决策耗时可以在本机直接测（我们的规则是纯条件分支，逐单元扫描，理论 O(n)，实测毫秒级）——**工作量小，且能显著提升与模板的对齐度**。排队论/算法对比属于模板独有叙述，不必补。

### 4.7 §3.2 关键帧截图（连续帧叙事）—— 部分缺
模板：每个智能体 3–4 张连续帧，按"来袭 → 状态修改 → 自动规避 / 结束"排列，形成时间序列证据。
我们的现状：5 张单帧实机图（`fig_apply-airspace/aircombat/ship/sam/timeline.png`），单帧无因果链。
可补程度：`兵棋录屏/` 有 4 段 mp4，可抽帧做成连续帧图——**工作量中等，价值高**（这是模板最有说服力的部分）。

### 4.8 §3.3 五维度人机结合效果评估 —— 缺
模板：操作负荷 / 决策质量 / 响应速度 / 风险管控 / 协同适配，每条带定量（操作量 −90%、准备耗时 30 min→2 min、响应 <1 s、误击率 0）。
我们的现状：无此类指标，且现有验证文档明确写"客户端不标注指令来源，拿不到命中/损失/得分数字"。
风险：**照抄模板口径等于编造数据**。建议改为"可核对的定性 + 可复现的定量"：把五维度降级为"分工边界/触发时机/响应延迟（可测）/可归因性/协同代价"，其中响应延迟给出实测值，其余标注证据等级。**需要你确认口径**。

### 4.9 §4.3 价值启示（军事/应急/工业三种场景映射）—— 缺
模板：三条启示 + 军事/应急救援/工业巡检的场景类比。
我们有素材：11.3 末段"可检验性本身应当写进设计指标"。
**工作量小，可写**（但要防止写空话）。

### 4.10 目录 / 页码 / 封面信息区 —— 缺
- 目录：现文档**完全没有**，模板有 2 页三级目录、点线引导、页码。
- 页码：现文档为 easy-paper 样式，需改为"页脚居中 9 pt、封面不显示但计入"。
- 封面：模板标题下方 4 行信息区，**标签已被白色矩形遮盖，无法从 PDF 提取**（文本层被替换为空格，见 `docs/资料/_pdf/智能体设计报告.md` 首页亦为空）。需你确认要填哪几项（建议：参赛队 / 队员 / 指导教师 / 日期）。

## 5 无法匹配模板结构的内容（我们的正文骨架 vs 模板骨架）

原文不是"按智能体逐个介绍"，而是"先立标尺，再逐个审计阈值"。两者维度不同：模板是 **智能体 → 规则 → 效果**；我们是 **阈值 → 物理标尺 → 受控实验 → 是否成立**。硬套会产生两处结构性矛盾：

### 5.1 §2.2「基础智能体」位置空置
模板 2.2 是篇幅最大的一节，我们没有任何对应内容（§4.4）。两种处置：

- **方案 A（推荐）**：把 2.2 定义为"基础智能体：物理作战域三维监控"，并在 2.2 开头一句说明"本队智能体体系与样板不同——我们只开发了五个战术级规则智能体，没有任务部署/条令/挂载层，战前规划仍由操作手完成"。**诚实且不空章**。
- 方案 B：删掉 2.2 这一层，把监控智能体并入 2.1 总体概述，2.3 直接升为 2.2。层级少一层，与模板不齐。

### 5.2 §2.4「性能分析」口径不同
模板 2.4 关心"算得快不快"（复杂度/耗时）；我们的第 8–9 章关心"结论稳不稳"（敏感性/稳健性/端到端）。标题可借"性能分析"，但内容必须说明这是**规则性能**而非**算法性能**，否则读者会找不到 O(n) 而认为缺项。

### 5.3 逐智能体章节的"章 → 节"降级
原文第 4–7 章（每章 3–4 节，深度足够独立成章）降为 2.3.x 后，最深层级变成"章.节.小节"三级，正好与模板 3 级目录对齐；但原文各章内部还有"其一/其二/其三"式并列论证，降级后需注意不超过 4 级（模板 4 级标题存在但很浅）。

### 5.4 附录无处安放
模板**没有附录**，正文结束即参考文献。我们的附录 A（参数总表）/ B（重现方法）/ C（术语表）是原文最"实"的部分之一，删掉可惜。**建议保留在参考文献之前，并在目录中列出**（比模板多一项，属可接受的增量）。

## 6 我们有、模板没有 —— 模板的欠缺（应重点保留）

这一节回答"现有内容里，哪些是模板欠缺、我们反而更有价值的"：

1. **方法主线：临界距离 $d_0$ 与"阈值的物理标尺"**。模板通篇没有一个可复算的判据，其规则阈值（3 km、0.8、1/2 $D_{max}$、3/5 $D_{max}$）全部凭经验给出，且不自证。原文第 1.4/3 章把五个阈值放到同一把尺子上，这是模板最缺的东西。
2. **受控对比与消融实验**。模板只有单向仿真曲线；原文有九策略横向对比、同距离消融（R vs B3）、固定随机种子、每格 800 次蒙特卡洛、单一变量原则。这是"证据等级"上的差异，不是篇幅差异。
3. **否定性结论**（模板完全没有）：
   - 分档规则不优于一个调好的常数（B1 0.924 > R 0.884）；
   - 垂直扭动在纯运动学下是负收益（R 0.645 < B3 1.000）；
   - 分层补射不占效率优势（0.751 < 0.849），收益是用 10 个百分点换 13 km；
   - $3/5 D_{max}$ 在纯能量模型下不是最优点（0.915 < 0.981）。
   模板全篇无一处"我们的规则有问题"，这恰恰是我们报告的可信度来源，**不能为了对齐模板而删掉**。
4. **稳健性与结论分级**。$±40\%$ 参数扫描、模型形式三处假设、结论分级表（稳 / 条件成立 / 仅算例成立），模板没有敏感性分析。
5. **端到端交战级验证**。1v1（我方胜 100%）→ 两波四打二（固定开火距离一方 0.00 架存活），模板只有"效果提升约 40%"式表述。
6. **局限与模型边界**。衰减律 29–37% 差异、导引头缺失、度量方式（模型 ≠ 计分）三处边界，模板没有"局限"章节，其 4.2 只是"挑战"。
7. **可复现性**。附录 A 参数总表（含随机种子）、附录 B 脚本与命令，模板没有。
8. **伪代码以文本代码块呈现**（模板用代码截图，不可检索、不可复制）。建议保留代码块，样式改为等宽 + 浅灰底 + 9 pt。
9. **公式排版与数学符号一致性**（$V_0$、$D_{max}$、$d_0$）。模板公式为 Word 公式对象，且多处乱码（`𝛿𝛿𝑖𝑖𝑖𝑖` 双写、下标错位），我们无需模仿。
10. **图表编号与交叉引用**（36 处 `@fig:/@tab:`）。模板靠"如下图/下表"指代，长文中极易指错（模板自己就有"图一/图二/图三"与正文"图二"错位的问题）。**建议保留编号**（见 §7.1）。

## 7 冲突项与需你决策的问题

### 7.1 图表是否编号（重要）
模板：**无编号**，图注/表题只有一句描述，正文用"如下图""下表"。
我们：18 图 13 表、36 处交叉引用、正文大量"表 @tab:margin 直接给出结论"。
- 若严格照模板 → 删编号，并把 36 处引用改成"下表/上表"，长文档中会出现"哪个上表"的歧义。
- 若保留编号 → 与模板不完全一致，但可读性与可追溯性显著更好，且**图注字体/位置/居中方式仍照模板**。
- **我的建议：保留编号，格式上写成"图 1　标题""表 1　标题"，字号 10.5 pt 宋体居中，与模板一致，仅多编号前缀。** 请你确认。

### 7.2 摘要与关键词去留
模板：封面后直接是目录，**无摘要、无关键词**。我们有 800 字摘要 + 6 个关键词。
模板的"摘要功能"由其 1.1–1.3 三节承担（想定→必要性→方案）。**建议：删除封面上的摘要，把内容分流到 1.1–1.3 与 4.1**；若赛会评审习惯要摘要，则单独做一页"摘要"置于目录后（比模板多一页）。请确认。

### 7.3 附录是否保留
模板无附录。建议保留（A 参数总表 / B 重现方法 / C 术语表），并在目录列出。请确认。

### 7.4 封面信息区填哪几项
模板 4 行标签被遮盖不可读。建议：`参赛队`、`队员`、`指导教师`、`日期`（标题为"联合作战人机协同智能体说明文档"还是沿用"智能体设计报告"？——建议用我们自己的题名，模板题名只是样板）。请确认。

### 7.5 红蓝双方不对称
模板按红蓝双方平行写（每节都有红/蓝两个子块 + 两张架构表）；我们只审计我方（红方/登陆方）五个智能体。建议在 1.3 明确写"本文审计范围为红方五智能体，蓝方为同构实现，不在本文逐条复述"，避免评审认为漏项。请确认是否接受。

### 7.6 3.3 五维度评估的数据口径
模板给出精确百分比（−90%、<1 s、误击率 0）。我们没有对应实测，硬填即造假。建议改为"证据等级 + 可测指标"，并把不可测项明确标为"未取证"。请确认可否偏离模板口径。

## 8 落地方式（技术方案，供确认后执行）

1. **自建 Typst 版式模块**（不依赖 easy-paper），逐项复刻 §1.1 参数：`page(margin: 2.5cm)`、`text(size: 12pt)`、`par(leading: 18.66pt, spacing: 6pt, first-line-indent: 24pt)`、`heading` 四级（15/14/12/12 pt）、`figure.caption` 10.5 pt 居中于图下、表格灰底全框线、`outline` 三级带点线引导、`numbering` 页脚 9 pt 居中且封面隐藏但计数。
2. **字体替换**（NixOS 无 SimSun/SimHei/Times）：
   - 宋体 → `Noto Serif CJK SC`
   - 黑体 → `Noto Sans CJK SC`
   - Times New Roman → `TeX Gyre Termes`（或 `Liberation Serif`）
   - 代码 → `DejaVu Sans Mono` + `Noto Sans Mono CJK SC`
   与现稿一致，视觉接近模板；若需逐像素一致，可提供 SimSun/SimHei 字体文件。
3. **交叉引用清理**：14 处硬编码"第 N 章"、1 处"第 4.2 节"全部替换为 `@sec:` 标签；章节重编号后由 Typst 自动生成编号。
4. **图片资产复用**：`paper/shared/figures/`、`schematics/` 全部可用；宽度按模板改为 15.4/15.8 cm（满版心）。
5. **验收**：生成后用同一套 PyMuPDF 量测脚本比对（页边距、字号、行距、标题字号、页码位置、目录缩进），输出差异表。
