## 2. 界面路径：用想定开一局 + 挂智能体（8 步）

1. `D:\LingYi\APlatformLobby.exe`（管理员）→ 登录页出现。
2. 点**底部【单机版启动】**（离线）/【局域网启动】（联机）。实测：这一步用 UI Automation 触发 `Invoke` 即可，无需人工点击。
3. 客户端主界面 → 菜单 **想定 → 加载想定** → 选 `.scen` → 弹出**选择推演方** = 想定已加载成功。
   （`想定→导入想定` 可直接加载任意本机 `.scen`；`加载最近` 是历史列表。）
4. 战前部署阶段：调整单元位置/航路/挂载/条令（飞机、舰船、潜艇可动，设施/卫星/武器不可动）。
5. **推演 → 推演速度**：调倍速 + 开始/暂停（比赛口径：5 倍速 ↔ 智能体最小决策间隔 5 秒）。
6. **智能体调度 → 智能体编辑**：
   - 把智能体 `.py` 放到 `D:\LingYi\intelligent\ai\agent\`（或 `<安装目录>\intelligent\`），
   - 点左下角 **“＋”** 导入单个智能体；或点 **“导入智能体配置”** 导入之前“保存配置”出的 json；
   - 右上方 **＋** 打开“决策脚本输入框”，把**实体单元 / 目标 / 参考点**加进该智能体（只有被加进去且处于“运行”的元素才受智能体控制）；
   - 点智能体后面的**启动**按钮。
7. **智能体调度 → 智能体消息输出**：看 `self.agent_message_text()` 的消息（最多保留最新 1000 条）。
8. 想调试就“启动→停止”一次，客户端会在 `intelligent\ai\config\<智能体名>#1\` 生成 `config_server.ini / config_player.ini / config_simulate.ini`，把它写进 `ai_apply_config.py: GLOBAL_CONFIG_PATH`，再用 `main.py` 在 PyCharm 里断点调试。

> ⚠️ 现状：`ai_apply_config.py` 里 `GLOBAL_CONFIG_PATH = D:\LingYi\intelligent\ai\config\anti_sub_agent#1`，**该目录不存在**；实际存在的是 `config\Mission_all_red#1`。要跑 `main.py` 调试路径得先改这一行。

## 3. 无界面路径（推荐用于 1000+ 局）

### 3.1 核心：`intelligent\ai\agent\config.py` 的开关表

`LingYiConfig.get_server_config()` 里（第 120~190 行）这些是批量跑的全部关键：

```python
"mode": 4                       # get_server_mode_config(): 1普通 2 K8S 3客户端 4单机版
"server": {
  "server_ip": "127.0.0.1",     # 管理服务
  "server_port": 20000,
  "room_name": "wargame-py",
  "data_link_type": 3,          # 0=DDS 1=组播 3=ZMQ
  "continuous": 0,              # 0=智能体算完才继续推演（可复现）；1=不等
  "save_situation_type": 0,     # 0不存 / 1仅完整帧 / 9仅状态帧 / 99全存
  "cplus_server": 1,            # 1=C++引擎(Plat.exe) 0=C#引擎
  "lypath": r"D:\LingYi\Data\lyengine",   # mode==4 时引擎目录
},
"simulate": {
  "clear_room": False, "process_id": 1,
  "main_client": True,          # 主客户端：由 python 负责开局和设倍速
  "load_scenario": True,        # True=由智能体端加载想定（必须新建房间重置）
  "scenario": "尤卡坦冲突-2025人机协同专项赛（人机版）",   # 想定名，不带 .scen
  "scen_check": True,
  "episodes": 10,               # ★ 规则智能体跑几局
  "compression": 60,            # ★ 1/2/5/10/15/20/60 倍速；10001=全速 10002=超速
  "need_compression": True,
  "decision_interval": 30,      # ★ 智能体决策间隔（推演秒）
  "step_interval": 1,
  "simulate_complex": 3,        # 1~6，想定越复杂允许等后台越久
  "training": True,             # True 才调用 agent.is_done() 提前结束本局
  "testing": True,              # ★ False：某局代码出错就跳下一局，不中断整批（批量必须 False）
  "events": False, "need_all_side": True,
  "save_result": False,         # ★ True → 每局结果写 gamedata.db
},
"RL_agents": {...}              # get_rl_agent()：强化学习智能体 + 受控单元名列表
"rule_config": {...}            # get_rule_dict()：规则智能体
```

- **想定从哪里找**：`scenario` 填 `Data\Scenarios\` 下的文件名（不含 `.scen`）。`scen_check=True` 时会去校验，找不到就 `reset=-1`。
- **规则智能体写法**（`get_rule_dict()`）：
  ```python
  "红方": {"redTactics": {"class": Mission_tactics_red.Agent, "unit": [], "contact": [], "point": []}}
  ```
  `unit/contact/point` 是“受控单元 / 情报 / 参考点”名列表；客户端调度时可改，代码里也可以留空让智能体自己按态势遍历（红方现在的 `Mission_all_red.py` 就是这么做的）。
- **强化学习**：`get_rl_agent()` 配 `class/unit/contact/point`，再配 `get_train_config()` 的 `num_workers`（并行房间数）、`training_mode`（local/normal/cluster）、`alg`、`stop_iters` 等。

**A. `start_LingYiAI.py`（框架自带主入口）**

**B. 自己写 runner（我实测用的，推荐）** —— 见 `D:\LingYi\intelligent\ai\pi_batch_test.py`（已留在机器上）：

```python
from agent.config import LingYiConfig

config = LingYiConfig.get_server_config({})
sim = config['game_server']['simulate']
sim.update(scenario='海洋空战', episodes=2, compression=10001,
           decision_interval=5, testing=False, save_result=True,
           load_scenario=True, main_client=True, clear_room=True)

env = Deduction(config)
for ep in range(1, EP+1):
    r = env.reset(ep)                     # 1成功 / 0管理服务 / -1推演服务 / -2无想定 / -3无初始态势
```

`BatResult` 字段（`entitys/data/gamedata.py`）：`bat_round / time / red_score / blue_score / red_name / blue_name / error_side / bat_result(1红胜 -1蓝胜 0平) / process_id`。

## 4. 三个必须知道的坑

### 4.1 `scenario` 是“想定名”不是路径
只写 `海洋空战`，不要写 `D:\...\海洋空战.scen`。校验失败时 `reset()` 返回 `-1`，日志里是“想定'xxx'加载失败，请检查想定文件是否存在”。

### 4.2 端口是写死的一段
单房间用 `127.0.0.1:20000`（管理）、`21001`（gRPC）、`22001`（DDS）。客户端那边会 `Searching for available port pair in range 21001 - 21500` 自动找空端口对——**说明多实例是设计支持的**，但 python 框架侧没暴露显式端口参数（`server` 里只有 `server_port`）。

### 4.3 ★ 幽灵坑：Session 0 起不来引擎（本次最关键的发现）

从 SSH 直接跑 `python.exe pi_headless_test.py` 时：

```
RESET = -1（推演服务连接失败）
Plat.exe stderr: CreateWindow() for QEventDispatcherWin32 internal window failed (拒绝访问。)
                 Qt: INTERNAL ERROR: failed to install GetMessage hook: 5
客户端日志: failed to connect to all addresses; ipv4:127.0.0.1:21001: Connection refused
```

`sshd` 跑在 **Session 0**（无交互桌面），`Plat.exe` 是 Qt 程序，哪怕没有可见窗口也必须能创建窗口站/消息队列，于是直接崩，`reset()` 永远 `-1`。

**解法（已实测通过）**：把 python 丢到 Session 1 里跑——用 `LogonType=Interactive` 的计划任务投递（和截图那套是同一个技巧，且必须用 **SID** 而不是 `域名\用户名`）：

```powershell
$sid  = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
$prin = New-ScheduledTaskPrincipal -UserId $sid -LogonType Interactive -RunLevel Highest
Register-ScheduledTask -TaskName 'PiBatch' `
  -Action (New-ScheduledTaskAction -Execute 'D:\LingYi\intelligent\ai\pi_run_batch.bat') `
  -Principal $prin -Force -Settings (New-ScheduledTaskSettingsSet -ExecutionTimeLimit (New-TimeSpan -Minutes 30))
Start-ScheduledTask -TaskName 'PiBatch'
```

对比同一份脚本：

| 启动方式 | 结果 |
| --- | --- |
| SSH 直连（Session 0） | `reset=-1`，`Plat.exe` 秒退 |
| 计划任务 Interactive（Session 1） | `reset=1`，173 步跑完 |
| 控制台里手工双击/`start`（Session 1） | 同上（推断，未单独验证） |

> 只要机器上有一个已登录的交互会话（现在是 Session 1 / console），这套就能用；**不需要** RDP 一直连着，但会话不能注销。

## 5. 日志 / 数据产物全清单（都是实测看到的）

| 内容 | 路径 | 何时产生 / 说明 |
| --- | --- | --- |
| ★ 框架逐步日志 | `intelligent\ai\logs\simulate.log` | 每步一行：`process:1-<pid>, round:N, time:xxx x, step index:k, step:0.203s, simulate:0.203s, update:0.000s, piRed step:0.000s`。可算每步耗时与总步数 |
| 智能体自己的日志 | 智能体的 `logging.info(...)` 走 **root logger → 默认 stderr**（批量时必须 `2> xxx.log` 重定向，否则全丢）；框架自带的 `Platform` logger 同时写 stderr 和 `logs\simulate.log` | 红方 `Mission_all_red.py` 打的 `威胁[...] / 规避[...] / 开火[...]` 走的就是这条 |
| 客户端调试日志 | `Logs\灵弈智能推演系统_YYYYMMDD.log` | 引擎启动参数、端口轮询 60 次、插件加载、内存看门狗、DB 快照 |
| 大厅日志 | `Logs\APlatformLobby_YYYYMMDD.log` | 登录、单机版启动 |
| ★ 引擎指令日志 | `Logs\#LOCAL\Plat#LuaHistory.log`、`Plat#RpcHistory.log`、`Plat.log` | **每一条 Lua/RPC 指令都有一条记录** —— 想核对“这条指令到底有没有下发成功”看这里 |
| 智能体消息栏 | `Logs\agentMsg.log` | `agent_message_text` 的输出（客户端“智能体消息输出”的内容） |
| 态势帧 | `Logs\SituationData\{THSituationFull, THSituationSide_<sideId>, SITUATION_INFO, SCENARIO_INFO}\*.json` | 客户端侧落盘，**只保留 24 小时**（日志里 `cleanSituationData ... keepHours: 24`）。字段定义见 `intelligent\ai\proto\Struct.proto`（`THSituationFull` 等），解析代码在 `engine\LingYi\entitys\gameenvs\common\Struct_pb2.py` |

## 6. 回放

- **文件层面**：`Data\Recordings\<...>\` 里的 `complete.dat + index` 就是完整的可回放录像，`simulation.ini` 里记录了想定标题、双方 sideId、推演时长、起始时刻，`rpccommand.dat` 记录所有指令。
- **界面层面**：回放来自插件 `libaplatform_plugin_evaluatereplay.dll`。
  - `configs\ap_configPlugin_lobbyMode.xml` 里它是**启用**的（在线版历史战绩 → 回放，支持倍速/暂停/拖拽/切视角）；
  - `configs\ap_configPlugin_defaultMode.xml`（**单机版默认用的就是这个**）里它被 **注释掉了**；
  - `ap_config.xml` 里的 `config_path` 决定当前用哪套插件配置。
- 所以：**单机版默认没有回放入口**。想试的话把 `D:\LingYi\ap_config.xml` 的
  `<config_path>./configs/ap_configPlugin_defaultMode.xml</config_path>`
  改成 `./configs/ap_configPlugin_lobbyMode.xml`（会同时带入 lobby/login 相关插件，**未验证是否可脱离服务器单独工作**）。改前先备份。
- 替代方案（更稳）：不用 UI 回放，直接把 agent 自己的日志 + `rpccommand.dat` + `simulate.log` 做离线分析；或者用 `client`+`观察`（局域网版）实时看。

## 8. 跑 1000+ 局的落地方案

**方案 A（最省事，先跑通）**：单进程 `episodes=1000`
- `testing=False`（单局异常不中断整批）、`save_result=True`（结果入 `gamedata.db`）、`compression=10001`、`decision_interval=5`
- 预计 **~21 小时**；录像约 0.5 MB/局 → 1000 局约 500 MB，能接受；想省就把 `Data\lyengine\Config\Server.ini` 的 `IsStartRecord` 改成 `False`
- 建议用一个外层批处理，按每 100 局重启一次 python（防内存/句柄泄漏），日志按批次重定向：
  ```bat
  for /L %%i in (1,1,10) do (
    D:\LingYi\intelligent\new_env\ray210\python.exe start_LingYiAI.py >> logs\batch_%%i.log 2>&1
  )
  ```

**方案 B（并行，需验证）**：
- 客户端支持自动选端口对 21001–21500，`get_train_config()` 的 `num_workers` 是“并行房间数”，说明多实例是设计内的；但**规则智能体 + Deduction 的多房间没实测**。
- 若要并行，两种做法：① 起 N 个 python 进程，每个用不同 `room_name`（端口可能撞车，需实测）；② 手工先起 N 个 `Plat.exe` 占不同端口对，再让 python 连过去（相当于 mode 3 客户端模式，需要额外验证）。

**必须注意的软限制**（附件2）：
- 一个客户端所有智能体合计 **每 10 秒最多 500 条指令**；
- 单条指令 **≤300 字符**（批量分配任务一次 ≤10 个单元、航路点 ≤8 个）；
- 决策间隔 **最小 5 秒**。
