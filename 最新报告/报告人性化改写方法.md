# 报告正文人性化改写方法（往返翻译 + 逐句精校）

本文档记录 `最新报告/paper/` 下 Typst 报告正文的改写流程、工具链、约束与实际效果，供后续继续改写或复用时参照。

- 首次应用：commit `61d207a`（重写 1.2 节、新增 1.3 节）
- 处理对象：该次提交在 `.typ` 文件中新增的正文段落
- 处理结果：35 段、4234 字 → 约 5200 字，`typst compile` 通过

---

## 1. 要解决的问题

原稿有一个稳定的写作习惯：**尽量省略字数**。表现为分句之间靠分号串接、主语承前省略、因果关系用破折号或并列结构隐含、括号里塞进补充说明。这种写法密度高，但代价是可读性差——读者必须自己补上被省掉的连接词，才能还原作者的意思。

改写的目标是：在**不改变事实、数字、术语、结论**的前提下，把被省略的语言成分显式补出来，让每个句子自身成立、句间关系明确。因此改写后的文本必然比原文更长，这不是冗余，而是把原本隐含的信息写出来。

需要强调的是，这不是「扩写」。判断标准是：

- ✅ 补出原文隐含的关系（因果、让步、条件、指代）
- ✅ 展开被压缩的分句，让每个句子有完整的主谓
- ❌ 增加原文没有的信息、推断、举例
- ❌ 用同义词堆叠凑长度

## 2. 方法：为什么用「小模型往返翻译」

直接用大模型润色有个通病：它会按自己的写作习惯重写，产出典型的大模型中文腔——四字短语堆叠、排比句、过度对称的结构。这类文本读起来「流畅」但缺少具体信息，反而比原稿更难读。

往返翻译（round-trip translation）绕开了这个问题：让一个小型**专用翻译模型**把中文译成日文，再译回中文。模型在这一过程中不做「润色」判断，只做翻译，因此：

1. 中文里被省略的语法成分，在日语中**必须显式存在**（日语不能省略主语和格助词）
2. 日文再译回中文时，这些成分会以中文的显式形式保留下来
3. 模型的翻译用词与原始写作习惯不同，AI 腔特征句法被替换

结果是一段语法完整、连接明确、但**没有大模型腔**的中文。这正是需要的效果。

### 为什么选混元 7B

`tencent/Hunyuan-MT-7B` 是专职机器翻译模型（非通用对话模型），符合两条要求：

- 参数规模小（≤9B），在硅基流动平台上免费额度充足
- 只做翻译、不做发挥，遵守「translate without additional explanation」这类指令

**已知弱点**（下节 5.1 详述）：对中文里高度压缩的表述（如「折合」「十条」）和分号串接的多重并列关系，容易误读。这是必须配合精校的原因。

## 3. 工具链

全部在命令行完成，脚本位于 `/tmp/rt/`（临时目录，未纳入版本库）。

### 3.1 占位符保护（`ph.sh`）

改写不得触碰的内容，先替换成占位符 `QQX0XQQ`、`QQX1XQQ`……，译完再原样还原。保护的类别：

| 类别 | 正则 | 例 |
|---|---|---|
| 数学 | `\$[^$]+\$` | `$U_R$`、`$d_0$` |
| 行内代码 | `` `[^`]+` `` | `` `initial()` ``、`` `step()` `` |
| 交叉引用 | `@[A-Za-z][\w:.-]*` | `@fig:arch`、`@tab:score` |
| 标签 | `<[A-Za-z][\w:.-]*>` | `<fig:evade-fsm>` |
| 数值区间 | `\d+[–-]\d+` | `3.3–6.1` |
| 百分数 | `\d+%` | `65.5%` |
| 带单位数字 | `\d+\s*(秒\|分钟\|海里\|km\|倍\|条\|项\|组)` | `180 分钟`、`500 条` |
| 领域术语 | 术语表（约 90 条） | `物理作战域三维监控`、`弹速`、`判据` |
| 裸数字 | 兜底 | `148`、`273` |

术语表内容（`/tmp/rt/term.txt`）需覆盖全篇的固定叫法，包括五个智能体全名、系统组件名、关键判据名。**术语表越密，结果越稳**——因为模型可自由发挥的空间越小。

### 3.2 编码与还原

```bash
# 编码：术语/数值/结构 → QQXkXQQ，同时写出 .map 对照表
./ph.sh enc <原文.txt> <编码.txt>

# 还原：按 .map 替换回原文本
./ph.sh dec <译文.txt> <还原.txt> <原文.txt.map>
```

两个实现要点：

**同一术语复用同一编号。** 首次实现的 bug 是每次 `re.sub` 命中都分配新编号，导致「伪代码」出现两次却是 `QQX0XQQ` 和 `QQX7XQQ`，还原后错位。改为维护「术语 → 编号」字典。

**相邻占位符必须合并。** 例如 `180 分钟折合墙钟 18 分钟` 会生成三个连续占位符 `QQX2XQQ折合QQX3XQQ QQX4XQQ`，模型在三连占位符上会丢项（实测丢了 `18 分钟`）。因此编码后做一次合并：相邻占位符（中间只隔空格/顿号）合并成一个，值取拼接文本。合并后为 `QQX18XQQ = 墙钟 18 分钟`。

### 3.3 双跳翻译（`a.sh`）

```
中文（占位符形式）
  → [分号句号化]  → Hunyuan-MT-7B → 日文
                                    → Hunyuan-MT-7B → 中文
                                                        → 还原占位符
```

**分号句号化**是必要的一步：原稿大量使用分号连接并列项，译为日语时容易把并列关系误读为归属关系。实测「180 分钟折合墙钟 18 分钟；平台决策间隔为 30 秒仿真时间」被误译为「决策间隔属于同一个平台…实际时间 3 秒属于另一个平台」。把 `；` 替换为 `。` 后再送译，该错误消失。

参数：`temperature=1.0`，`max_tokens=5000`。

### 3.4 后处理（`fix.sh`）

占位符还原后，模型常在占位符两侧留空格，形成「程序 推演 会被执行」这类。清理规则：删除**汉字与汉字之间**的空格、删除中文标点前空格，保留中英文之间的空格（Typst 排版需要）。

## 4. 段落切分原则

**处理**：

- 空行分隔的正文段落
- 以 `_强调_` 开头的段落（Typst 中 `_x。_` 是小标题样式）

**不处理**：

- 标题行（`= `、`== `、`=== `）
- `#figure()` / `#table()` 块内部，包括 `caption: [...]`
- 代码块 ` ``` `
- 表格单元格（`[决策], [上百条配置…], ...`）——表格是并列短句，展开会破坏对齐

从 git 取新增段落：

```bash
git show <commit> --format="" -- <file.typ> \
  | grep -E '^\+' | grep -v '^+++' | sed 's/^+//' \
  | grep -vE '^\s*$' | grep -vE '^=|^#|^\s*\)|^\s*image|^\s*caption'
```

## 5. 精校：方法 A 的必需环节

混元的输出是**风格底稿**，不是终稿。必须逐段对照原文修正事实。这一步不能省，也不能交给模型（试过让另一个模型对照原文校正，见 5.2）。

### 5.1 混元的典型误译

实测出现过的偏移，按类型归纳：

| 原文 | 误译 | 类型 |
|---|---|---|
| 失效模式是「漏」 | 问题包括「信息泄露」 | 单字术语被扩解 |
| 二十余条支援任务 | 20 多个支援任务模块 | 约数被具体化 + 单位错 |
| 推演以 10 倍速运行 | 推演的处理速度与 10 倍相同 | 比较关系被误读 |
| 180 分钟折合墙钟 18 分钟 | 180 分钟的处理速度则相当于墙钟 18 分钟 | 分号并列误读为归属（**已用句号化解决**） |
| 三条轴线…三个切面 | 三条轴线…三个相互关联的处理流程 | 比喻被字面化 |
| 本队的取舍 | 本队与取舍之间的关系 | 领属关系被误读 |
| 逐条拆开、逐条对照检验 | 划分为多个部分（即逐条），逐条可以比对 | 动宾结构被拆解 |
| 某区域可以不要 | 哪些区域可以被忽略 | 语气漂移 |
| 机械单独做也不行 | 仅依靠机械设备进行处理也是不够的 | 名词误读为设备 |

**归纳出的规律**：混元在「压缩表述」处最容易出错，具体是约数（二十余）、比喻（切面）、领属（本队的）、单字概念（漏）、动宾短语（拆开检验）。精校时优先检查这些位置。

### 5.2 为什么不做二次模型校正

尝试过方案：混元双跳后，再用 `zai-org/GLM-4.5-Air` 对照原文校准。结果是两个极端：

- 指令强调「以原文为准」→ GLM 直接抄回原文，改写完全消失
- 指令强调「沿用译稿句式」→ GLM 把混元的错误当成事实，还自行编造英文注释、Markdown 列表

原因是 GLM 无法区分「原文的事实」与「译稿的语言组织」，这个区分只有人类读者能可靠完成。因此**精校由人完成**。

### 5.3 精校的检查清单

逐段对照时，按以下顺序核对：

1. **数字**：所有阿拉伯数字、中文数字（二十余、上百、十余）的数量级与单位
2. **术语**：智能体名、组件名、判据名、章节号引用是否原样
3. **逻辑关系**：因果、条件、让步、转折的指向是否与原句一致（最容易在分号处出错）
4. **指代**：「它」「这」「两者」指向的对象是否与原句相同
5. **否定与限定**：「无法」「不必」「仅」「只」的位置是否保留了原句的限定范围
6. **未增加内容**：改写里是否有原文没有的推断（如有，删去）

### 5.4 允许的展开

以下是允许的，属于「把隐含的写出来」：

> 原：而这类错误比「跑不起来」更难发现。
> 改：而这类错误比「跑不起来」更难发现，因为推演照常推进，只是前提已经不是原本想设的那个战场。

原文用「更难发现」已经隐含了「表面上正常」这层意思，展开后读者不必自己推断。

> 原：而两者恰好相反。
> 改：而这两件做不好的事恰好互为反面。

原文「两者」指向模糊，明确指向是必要的澄清。

### 6.2 样例

**原文**

> 这三条轴线不是并列的功能清单，而是人机能力边界的三个切面：在每一条轴线上，人都有一项做不好的事，智能体也有一项做不好的事，而两者恰好相反。本节只说明这种相反为何构成「必须协同」的理由，具体怎么落地留到 1.3 节。

**改写后**

> 需要强调的是，这三条轴线并不是一份并列的功能清单，而是人机能力边界的三个切面。之所以这样说，是因为在每一条轴线上，人都有一项做不好的事，智能体也有一项做不好的事，而这两件做不好的事恰好互为反面。本节只说明这种互为反面为何构成了「必须协同」的理由，至于具体怎么落地，则留到 1.3 节展开。

变化点：

- 冒号改为句号 + 「之所以这样说，是因为」——把因果显式化
- 「两者」→「这两件做不好的事」——补全指代
- 「而两者恰好相反」→「而这两件…恰好互为反面」——消解「相反」的歧义（是方向相反还是性质相反）
- 「具体怎么落地留到」→「至于具体怎么落地，则留到」——补出转折连词

**原文**

> 人单独做决策，失效模式是「漏」与「不一致」。……漏掉其中一条不会报错、也不会中断推演，只会在某个时刻以一次失败的拦截显现出来——这正是人工操作最难自查的一类错误。

**改写后**

> 人单独做决策时，其失效模式表现为「漏」与「不一致」。……在这样的规模下，漏掉其中一条既不会报错，也不会中断推演，它只会在某个时刻以一次失败的拦截显现出来；而这一类错误，恰恰是人工操作最难自查的。

变化点：

- 「既…也…」+「在这样的规模下」——把上文提到的规模与本句的因果关系显式接上
- 破折号改为分号 +「而」——原句的破折号同时承担「解释」与「转折」两种功能，显式化为转折

## 8. 遗留与注意

- **术语表需随内容扩充**。新增章节涉及新术语时，先补 `term.txt` 再跑，否则混元会自行变译。
- **混元温度**：`1.0` 用于正文（保留改写力度），温度更低会更接近直译、改写力度减弱。
- **本流程不适用于表格与图注**。图注是压缩的说明文字，展开会显得啰嗦；表格单元格展开会破坏布局。
- **未提交**：当前改动在工作区，`git checkout -- 最新报告/paper/sections/` 可回退。

## 9. 第二轮：全篇按可读性规则直接改写（2026-11）

第 2–7 节的往返翻译只处理了新增段落。这一轮把整个 `paper/` 正文过了一遍，改法也换成「按显式规则逐段重写」，不再走翻译链路——因为问题已经不在句式翻译，而在**论述顺序**与**句间连接**。

### 9.1 三条硬规则

1. **禁止「标签 + 句号」起段**。`背景。这份想定……`、`失效模式。有两处。`、`其一，数据版本。本节……` 这类写法一律展开成完整主谓句：`要判断人机协同是否必要，可以先看这份想定给人留下了多大的工作量。`
   - 例外：确有信息量的分论点总领段可以保留前置，但必须自身成立，例如 `（1）决策：由人给意图，由机器给精度。`
2. **先因后果、先证据后观点**。凡原稿把结论放在段首、理由跟在后面的，一律倒过来写。典型如「比兵力分值更重要的是占领分」→ 先讲兵力分值怎么算、占领分怎么算、各自量级如何，最后落到「因此占领分的意义在于它是确定性最高的得分途径」。
3. **连接词显式化**。段间补「先看／再看／最后是」「正因为如此」「反过来」「换句话说」；句间把破折号承担的因果、转折拆成独立小句。宁可多写半句，也不让读者自己补关系。

### 9.2 范围与不动的部分

- 处理：所有正文段落、列表项的引导句、摘要（`main.typ` 的 `abstract`）。
- 不动：标题、表头与单元格、图注、伪代码、数学式、`@ref`／`<label>`、行内代码、命令与字段名。
- 校验：`@ref` 与 `<label>` 数量逐文件比对无变化；`typst compile` 通过；成品 182 页。

### 9.3 效果

段落数不变（一段仍是一行），字符数增幅约 1%–4%（如 `03-basic.typ` +3.7%、`04-core.typ` +2.5%、`05-perf.typ` +0.9%）。增幅远小于第 6 节的 25%，因为这一轮做的是**语序重排与连接补齐**，而不是把隐含内容全部展开——原稿的信息密度本身已经够，缺的是让读者一次读懂的顺序。

## 10. 写作规范（作者口径汇总，以此为准）

本节把前后二十余次退回、改稿、复盘收敛成一套可执行的规范。§9 与本节冲突处，以本节为准。每条规则后面用 `（原 10.x）` 标注它的来历，方便回溯当时的例子。

### 10.0 三条总判据

一切具体规则都服务于这三条；三条冲突时，按顺序让位。

1. **读者一次读懂**：句子要能回答"谁做了什么、凭什么"，不能让读者回读或自己补主谓。
2. **数字可回溯**：正文每个数字都要能指到某个 CSV 的某一列，或指到某个推导式。
3. **语感来自双跳**：句子骨架取自中日中往返翻译的结果，不由作者（我）自由发挥；精校只做有限修补。

### 10.1 工作流

#### 10.1.1 三步顺序（原 10.8、10.16）

**先自写 → 再双跳 → 最后精校**，顺序不能颠倒，也不能跳步。

- **自写**：先按逻辑把段落写对——数字、实体、因果以自写稿为准。
- **双跳**：中文 → 日文 → 中文往返一次。它的价值是补出主语、把分句接成从句、把省略成分补齐，即"句子骨架"。
- **精校**：以双跳稿为底稿做有限修补（修补范围见 10.1.3）。

判断标准不是"双跳措辞比我的好"，而是"双跳的句子比我的完整"。若完整，就按它的骨架重写，只把名词换回来。

例（`只抓一次`段）
- 自写：`所谓"只抓一次"，指的是物理作战域三维监控是全系统唯一直接读取仿真内核的单位。它把全量态势结构化之后写入真源，四个决策域与前端小窗都从真源读取。`
- 按双跳骨架：`所谓"只抓一次"，指的是整个系统里只有物理作战域三维监控这一个组件直接读取仿真内核的数据。它把读到的全量态势结构化之后写进态势真源，另外四个组件，也就是四个决策域与前端小窗，都不再去调用平台接口，而是从真源里取数。`

#### 10.1.2 精校的边界（原 10.20）

**只做四件事**：

1. 术语与专名替换（含作者已统一的词表，见 10.4.3）；
2. 明显的病句、错字、主谓残缺；
3. 明显的事实错误（数字、方向、因果）；
4. 同一主语的两个短句的必要合并。

**不做**：重排句序、压缩长度、替换说法、删双跳的修饰语、加自己的解释或总结。

作者改稿示例（`ch4` 第二条兜底）
- 双跳：`第二条是所谓的"保底处理"条款。这些条款与第一条并行存在，并不包含在第一条的规则中。无论第一条的计算结果如何，只要弹目距离达到了 25 km 的状态，或者在预期的时间达到了 60 s 的状态，第二条的规则就会被执行。设置这些"保底处理"条款的原因有两个：首先，第一条仅规定了在"导弹的可到达范围之外时应该向哪个方向转移"；其次，即使计算尚未完成，也必须采取某种行动——…就需要某种保障机制来确保系统的正常运行。`
- 作者定稿：`第二条是两条兜底处理条款。它们与第一条并行存在，并不包含在第一条判据中：无论第一条算出什么结果，只要弹目距离达到了 25 km，或者预计命中时间达到了 60 s，这条规则就会被执行。设置这两条兜底条款的原因有两点：首先，第一条仅规定了"应该在导弹可达范围外的哪里掉头"，并不保证能够完全计算；其次，即使计算尚未完成，也必须有动作——平台上判定与动作都只有一个粒度的周期而来不及精确计算的时候，需要一种保障机制确保系统的正常运行。`

差异只有五类：术语替换（保底处理→兜底处理、可到达范围→可达范围、第一条的规则→第一条判据）、合并两个短句、删赘语（所谓的、的状态、在预期的时间）、补一个漏掉的分句（并不保证能够完全计算）、修病句错字。

**自检**：改完与双跳逐句对齐，差异必须能像上表那样逐条列出；列不出来的改动，就是重写而不是精校。

#### 10.1.3 分批交付与并行编辑（原 10.9）

- **一节一批**：改完即 `typst compile`，并给出"双跳 → 终稿"对照与改动清单，供作者验收。
- 写回用**段首句定位 + 整段替换**，不按行号（行号会被并行修改冲掉）。
- **不回退作者本人的改动**（如把"这份想定"改成"本想定"、把术语全局改为"判定距离"）。
- 作者在手改的文件上，我的写入可能被覆盖；发现段落内容与我写入的不一致时，先读、再问，不覆盖。

#### 10.1.4 批量替换的纪律（原 10.19 后半）

- 句子级改动**必须以整段为单位**提交。用句子当锚点会吞掉该段后续文字——本轮曾把 `*两类测量不能混用。*` 之后的整段删空，只剩一句小标题。
- 每批改完扫一遍"异常短段"（少于 45 字且不像标题、公式、图注），确认没有残留。
- 机械指标（破折号数、所谓数、句长分布）是**体检表不是施工图**：正则只用来列候选，不能直接下刀。曾把"破折号≈0"当目标，逐条替换，结果改出残句与悬空指代（详见附录 A-1）。

### 10.2 句子层

#### 10.2.1 主语不能省，指代必须唯一（原 10.13、10.18、10.17）

- 每句都要能回答"谁做了什么"；状语（`把……／在……／对于……`）不能代替主语。
- `它／这／该／此／上述／前者／后者` 的先行词必须在同段紧邻且唯一；跨段一律用具体名词；句尾不许"取决于它"。
- 名词缺定语时，用本段已有的名词补上（`这四个方面的共同结构`、`态势真源的写入周期`）。
- **审计法**：正则列出全部代词，逐条问"只凭本段前 20 字能确定所指吗"，不能就写全。
- 主语不许是"本文／本节／这一点"。元语言禁用清单：`需要说明／必须指出／值得注意／先交代／下文／上文／如前所述／会被读成／读者`。

#### 10.2.2 禁拟人、禁口语判断（原 10.21 二、三）

主语是数据或规则时，谓语不许用动作词。

| 禁用 | 改为 | 理由 |
|---|---|---|
| 判定距离跟着 $d_0$ 走／跟着缩 | 与 $d_0$ 成正比／随之缩小 | "跟"只承诺同向，丢掉比例与系数 |
| 由射程项接管／被射程项压住 | 由射程项决定 | "接管"暗示有意志 |
| 兜底条替它做决定 | 由兜底条来判定 | 同上 |
| 在那段交会里说话 | 在那段交会里起作用 | 纯口语 |
| 把均值抬到／把它抬到 | 升到 | 动作词换变化词 |
| 把开火点推到…外侧 | 移到 | 同上 |
| 从 3 959 条跳到 12 168 条 | 增加到 | "跳"暗示突变 |
| 判定距离涨了 19.1 km | 增加 19.1 km | — |
| 只上过一个 34 分的台阶 | 只提高过一档，幅度 34 分 | "台阶"是比喻 |
| 期望抬升 | 期望偏差 | 统计术语有定名 |
| 被反舰火力吃掉 | 被反舰火力击沉 | 战果要准确 |
| 下令就跟着堵 | 下令也会随之延迟 | — |

口语判断：`设对了／改对了` → `设置正确／是否改对`。

#### 10.2.3 不许电报化，也不许超长（原 10.1、10.5）

- 判断句前面要先给出**可核对的数量**或**可复述的因果**，不能直接下断语（`比 X 更重要的是 Y` 这类）。
- "更重要的是／关键在于"之前，必须已经立好被比较的两项。
- 一段最多一处"结论先行 + 后补解释"，其余改为先铺垫、后落地。
- 单句超过 160 字要拆，但**拆不等于切成电报**：拆出来的每句仍要有主语与限定语。

#### 10.2.4 修辞的边界（原 10.14、10.15、10.12）

- **"所谓 X，指的是……"是首选句式**，可反复用。判据只有一条：这个词是不是第一次出现、需要读者停一下的界定对象。是就用，哪怕一节里第六次。
- **破折号**：先判关系再决定用不用——解释/命名/列举用冒号，独立事实用句号，同位语用"即／也就是／包括"，因果转折必须写连接词。只禁两种用法：代连接让读者猜关系、代主语。**数量不设上限，也不要求清零**。
- **虚指量词不用**：`一个事实／一处口径／一件事情／一种情况` → 换成内容本身。

### 10.3 段落层（原 10.2、10.3、10.7）

- **禁"标签 + 句号"起段**：`背景。`／`失效模式。`／`其一，数据版本。` 一律展开成完整主谓句。`其一/其二` 改为"第一处／第二处 + 具体对象"。
- **连接必须落到字面**：因果、让步、条件、指代都写出来；换依据来源要有一句"换轨"的话。
- **段落要有推理链**（局面 → 结构 → 约束 → 结论），不能是知识陈列；不使用"先得把两个概念说清"这类元话语。

### 10.4 名词与术语

#### 10.4.1 首现即解释（原 10.4）

关键名词第一次出现就交代；解释短则句内"即…"，长则单独成句。

#### 10.4.2 不用翻译腔的抽象壳子（原 10.10）

`条款`→具体项目；`情形／事项／因素／维度／层面`→落回具体对象。

#### 10.4.3 术语表（作者定稿）

| 旧 | 新 | 说明 |
|---|---|---|
| 门限 | 判定距离 | 全文已替换（179 处），新写内容不得再用"门限" |
| 包线 | 导弹可达范围 | 全文已替换（31 处） |
| 口径 | 统计范围／统计定义／取数方式 | "口径"生硬，按语境替换，现已清零 |
| 量子 | 每周期接近距离 | — |
| 兜底／保底 | 暂未定 | "兜底"是口语动宾短语当名词，且与法律术语"兜底条款"撞车；"保底"亦偏口语 |

### 10.5 标题

- **禁"数词三连"清单式**：`一条插值判定距离、两条硬兜底、一种机动方式`、`三类单元、三个模式名、两条切换路径`。这类标题只说明"有几个成分"，不说明关系；数字写进标题后，读者会拿它核对正文。
- 改为**关系句或问题句**：`判定距离取 $1.2 d_0$，另加两条兜底`、`三个模式名，三类单元各用其中两个`、`三类威胁怎么识别，各自怎么应对`。
- **禁自我评价**：`诚实结论与边界` → `结论与边界`。
- 标题里的数目必须与正文一致（`没找到的东西` 原列两件、正文三件，标题即错）。

### 10.6 图表与讲图

- **主语是图，谓语是"显示/给出"，宾语是"什么量的什么关系"，随后紧跟读数**：`@fig:X 显示〈关系〉：〈读数〉，〈它支持的结论〉。`
  例：`@fig:fire-dist 给出每次开火的发射距离：固定 111 km 的两臂分布整体右移，中位数在 83–88 km；按 $0.8 d_0$ 判定的臂压在 70 km 附近。`
- **禁作者动作**：`把…画出来`、`逐条画了出来`、`各画一圈`、`为半径画出`、`把"判定距离 ÷ $d_0$"画出来`。
- **禁"看得更清楚 / 更直观"**：`把裕度对弹速画出来（@fig:d0 的 b 面板）看得更清楚` → `@fig:d0 的（b）面板直接显示裕度随弹速的变化`。判据是"谁看"被省掉，且"更清楚"没有比较对象。
- 图注只写画面里能直接读出的东西，不写推断；表格口径与表体必须自洽，必要时在题注写明计数方式（逐行计数／去重）与尾段处理。

### 10.7 数据与统计口径

- 每个数字必须能指到 CSV 的某一列或某个推导式；写不清出处的数字一律不写。
- 改数与改文必须同批完成：正文、表、表注、图注里的同一数字要一起改。
- 统计结论只报方向与区间；样本量不足时明确写"分辨不出"，不报百分比。
- 术语"口径"已弃用，改写为"统计范围""统计定义""取数方式"（见 10.4.3）。

### 10.8 一批改完的自检（原 10.11）

机械扫描（列候选，不下刀）：
1. 破折号、`所谓`、元语言词、拟人动词、动作词（抬/推/掉/跳/台阶）；
2. 平均句长低于 30 字或单句超过 160 字的段落；
3. 以"标签 + 句号"起段的段落；
4. 异常短段（少于 45 字且不是标题/公式）；
5. 术语残留（门限、包线、口径、量子）。

人工判据：
6. 只看每段首句与末句，能否复述这一节的论证线；
7. 每个代词能否在本段前 20 字内确定所指；
8. 讲图的句子，主语是不是图、宾语是不是"什么关系"。
