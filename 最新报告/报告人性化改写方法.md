# 报告正文人性化改写方法（往返翻译 + 逐句精校）

本文档记录 `最新报告/paper/` 下 Typst 报告正文的改写流程、工具链、约束与实际效果，供后续继续改写或复用时参照。

- 首次应用：commit `61d207a`（重写 1.2 节、新增 1.3 节）
- 处理对象：该次提交在 `.typ` 文件中新增的正文段落
- 处理结果：35 段、4234 字 → 约 5200 字，`typst compile` 通过

---

## 1. 要解决的问题

原稿有一个稳定的写作习惯：**尽量省略字数**。表现为分句之间靠分号串接、主语承前省略、因果关系用破折号或并列结构隐含、括号里塞进补充说明。这种写法密度高，但代价是可读性差——读者必须自己补上被省掉的连接词，才能还原作者的意思。

改写的目标是：在**不改变事实、数字、术语、结论**的前提下，把被省略的语言成分显式补出来，让每个句子自身成立、句间关系明确。因此改写后的文本必然比原文更长，这不是冗余，而是把原本隐含的信息写出来。

需要强调的是，这不是「扩写」。判断标准是：

- ✅ 补出原文隐含的关系（因果、让步、条件、指代）
- ✅ 展开被压缩的分句，让每个句子有完整的主谓
- ❌ 增加原文没有的信息、推断、举例
- ❌ 用同义词堆叠凑长度

## 2. 方法：为什么用「小模型往返翻译」

直接用大模型润色有个通病：它会按自己的写作习惯重写，产出典型的大模型中文腔——四字短语堆叠、排比句、过度对称的结构。这类文本读起来「流畅」但缺少具体信息，反而比原稿更难读。

往返翻译（round-trip translation）绕开了这个问题：让一个小型**专用翻译模型**把中文译成日文，再译回中文。模型在这一过程中不做「润色」判断，只做翻译，因此：

1. 中文里被省略的语法成分，在日语中**必须显式存在**（日语不能省略主语和格助词）
2. 日文再译回中文时，这些成分会以中文的显式形式保留下来
3. 模型的翻译用词与原始写作习惯不同，AI 腔特征句法被替换

结果是一段语法完整、连接明确、但**没有大模型腔**的中文。这正是需要的效果。

### 为什么选混元 7B

`tencent/Hunyuan-MT-7B` 是专职机器翻译模型（非通用对话模型），符合两条要求：

- 参数规模小（≤9B），在硅基流动平台上免费额度充足
- 只做翻译、不做发挥，遵守「translate without additional explanation」这类指令

**已知弱点**（下节 5.1 详述）：对中文里高度压缩的表述（如「折合」「十条」）和分号串接的多重并列关系，容易误读。这是必须配合精校的原因。

## 3. 工具链

全部在命令行完成，脚本位于 `/tmp/rt/`（临时目录，未纳入版本库）。

### 3.1 占位符保护（`ph.sh`）

改写不得触碰的内容，先替换成占位符 `QQX0XQQ`、`QQX1XQQ`……，译完再原样还原。保护的类别：

| 类别 | 正则 | 例 |
|---|---|---|
| 数学 | `\$[^$]+\$` | `$U_R$`、`$d_0$` |
| 行内代码 | `` `[^`]+` `` | `` `initial()` ``、`` `step()` `` |
| 交叉引用 | `@[A-Za-z][\w:.-]*` | `@fig:arch`、`@tab:score` |
| 标签 | `<[A-Za-z][\w:.-]*>` | `<fig:evade-fsm>` |
| 数值区间 | `\d+[–-]\d+` | `3.3–6.1` |
| 百分数 | `\d+%` | `65.5%` |
| 带单位数字 | `\d+\s*(秒\|分钟\|海里\|km\|倍\|条\|项\|组)` | `180 分钟`、`500 条` |
| 领域术语 | 术语表（约 90 条） | `物理作战域三维监控`、`弹速`、`判据` |
| 裸数字 | 兜底 | `148`、`273` |

术语表内容（`/tmp/rt/term.txt`）需覆盖全篇的固定叫法，包括五个智能体全名、系统组件名、关键判据名。**术语表越密，结果越稳**——因为模型可自由发挥的空间越小。

### 3.2 编码与还原

```bash
# 编码：术语/数值/结构 → QQXkXQQ，同时写出 .map 对照表
./ph.sh enc <原文.txt> <编码.txt>

# 还原：按 .map 替换回原文本
./ph.sh dec <译文.txt> <还原.txt> <原文.txt.map>
```

两个实现要点：

**同一术语复用同一编号。** 首次实现的 bug 是每次 `re.sub` 命中都分配新编号，导致「伪代码」出现两次却是 `QQX0XQQ` 和 `QQX7XQQ`，还原后错位。改为维护「术语 → 编号」字典。

**相邻占位符必须合并。** 例如 `180 分钟折合墙钟 18 分钟` 会生成三个连续占位符 `QQX2XQQ折合QQX3XQQ QQX4XQQ`，模型在三连占位符上会丢项（实测丢了 `18 分钟`）。因此编码后做一次合并：相邻占位符（中间只隔空格/顿号）合并成一个，值取拼接文本。合并后为 `QQX18XQQ = 墙钟 18 分钟`。

### 3.3 双跳翻译（`a.sh`）

```
中文（占位符形式）
  → [分号句号化]  → Hunyuan-MT-7B → 日文
                                    → Hunyuan-MT-7B → 中文
                                                        → 还原占位符
```

**分号句号化**是必要的一步：原稿大量使用分号连接并列项，译为日语时容易把并列关系误读为归属关系。实测「180 分钟折合墙钟 18 分钟；平台决策间隔为 30 秒仿真时间」被误译为「决策间隔属于同一个平台…实际时间 3 秒属于另一个平台」。把 `；` 替换为 `。` 后再送译，该错误消失。

参数：`temperature=1.0`，`max_tokens=5000`。

### 3.4 后处理（`fix.sh`）

占位符还原后，模型常在占位符两侧留空格，形成「程序 推演 会被执行」这类。清理规则：删除**汉字与汉字之间**的空格、删除中文标点前空格，保留中英文之间的空格（Typst 排版需要）。

## 4. 段落切分原则

**处理**：

- 空行分隔的正文段落
- 以 `_强调_` 开头的段落（Typst 中 `_x。_` 是小标题样式）

**不处理**：

- 标题行（`= `、`== `、`=== `）
- `#figure()` / `#table()` 块内部，包括 `caption: [...]`
- 代码块 ` ``` `
- 表格单元格（`[决策], [上百条配置…], ...`）——表格是并列短句，展开会破坏对齐

从 git 取新增段落：

```bash
git show <commit> --format="" -- <file.typ> \
  | grep -E '^\+' | grep -v '^+++' | sed 's/^+//' \
  | grep -vE '^\s*$' | grep -vE '^=|^#|^\s*\)|^\s*image|^\s*caption'
```

## 5. 精校：方法 A 的必需环节

混元的输出是**风格底稿**，不是终稿。必须逐段对照原文修正事实。这一步不能省，也不能交给模型（试过让另一个模型对照原文校正，见 5.2）。

### 5.1 混元的典型误译

实测出现过的偏移，按类型归纳：

| 原文 | 误译 | 类型 |
|---|---|---|
| 失效模式是「漏」 | 问题包括「信息泄露」 | 单字术语被扩解 |
| 二十余条支援任务 | 20 多个支援任务模块 | 约数被具体化 + 单位错 |
| 推演以 10 倍速运行 | 推演的处理速度与 10 倍相同 | 比较关系被误读 |
| 180 分钟折合墙钟 18 分钟 | 180 分钟的处理速度则相当于墙钟 18 分钟 | 分号并列误读为归属（**已用句号化解决**） |
| 三条轴线…三个切面 | 三条轴线…三个相互关联的处理流程 | 比喻被字面化 |
| 本队的取舍 | 本队与取舍之间的关系 | 领属关系被误读 |
| 逐条拆开、逐条对照检验 | 划分为多个部分（即逐条），逐条可以比对 | 动宾结构被拆解 |
| 某区域可以不要 | 哪些区域可以被忽略 | 语气漂移 |
| 机械单独做也不行 | 仅依靠机械设备进行处理也是不够的 | 名词误读为设备 |

**归纳出的规律**：混元在「压缩表述」处最容易出错，具体是约数（二十余）、比喻（切面）、领属（本队的）、单字概念（漏）、动宾短语（拆开检验）。精校时优先检查这些位置。

### 5.2 为什么不做二次模型校正

尝试过方案：混元双跳后，再用 `zai-org/GLM-4.5-Air` 对照原文校准。结果是两个极端：

- 指令强调「以原文为准」→ GLM 直接抄回原文，改写完全消失
- 指令强调「沿用译稿句式」→ GLM 把混元的错误当成事实，还自行编造英文注释、Markdown 列表

原因是 GLM 无法区分「原文的事实」与「译稿的语言组织」，这个区分只有人类读者能可靠完成。因此**精校由人完成**。

### 5.3 精校的检查清单

逐段对照时，按以下顺序核对：

1. **数字**：所有阿拉伯数字、中文数字（二十余、上百、十余）的数量级与单位
2. **术语**：智能体名、组件名、判据名、章节号引用是否原样
3. **逻辑关系**：因果、条件、让步、转折的指向是否与原句一致（最容易在分号处出错）
4. **指代**：「它」「这」「两者」指向的对象是否与原句相同
5. **否定与限定**：「无法」「不必」「仅」「只」的位置是否保留了原句的限定范围
6. **未增加内容**：改写里是否有原文没有的推断（如有，删去）

### 5.4 允许的展开

以下是允许的，属于「把隐含的写出来」：

> 原：而这类错误比「跑不起来」更难发现。
> 改：而这类错误比「跑不起来」更难发现，因为推演照常推进，只是前提已经不是原本想设的那个战场。

原文用「更难发现」已经隐含了「表面上正常」这层意思，展开后读者不必自己推断。

> 原：而两者恰好相反。
> 改：而这两件做不好的事恰好互为反面。

原文「两者」指向模糊，明确指向是必要的澄清。

| `sections/01-design.typ` | 31 | 7561 | 8147 |

### 6.2 样例

**原文**

> 这三条轴线不是并列的功能清单，而是人机能力边界的三个切面：在每一条轴线上，人都有一项做不好的事，智能体也有一项做不好的事，而两者恰好相反。本节只说明这种相反为何构成「必须协同」的理由，具体怎么落地留到 1.3 节。

**改写后**

> 需要强调的是，这三条轴线并不是一份并列的功能清单，而是人机能力边界的三个切面。之所以这样说，是因为在每一条轴线上，人都有一项做不好的事，智能体也有一项做不好的事，而这两件做不好的事恰好互为反面。本节只说明这种互为反面为何构成了「必须协同」的理由，至于具体怎么落地，则留到 1.3 节展开。

变化点：

- 冒号改为句号 + 「之所以这样说，是因为」——把因果显式化
- 「两者」→「这两件做不好的事」——补全指代
- 「而两者恰好相反」→「而这两件…恰好互为反面」——消解「相反」的歧义（是方向相反还是性质相反）
- 「具体怎么落地留到」→「至于具体怎么落地，则留到」——补出转折连词

**原文**

> 人单独做决策，失效模式是「漏」与「不一致」。……漏掉其中一条不会报错、也不会中断推演，只会在某个时刻以一次失败的拦截显现出来——这正是人工操作最难自查的一类错误。

**改写后**

> 人单独做决策时，其失效模式表现为「漏」与「不一致」。……在这样的规模下，漏掉其中一条既不会报错，也不会中断推演，它只会在某个时刻以一次失败的拦截显现出来；而这一类错误，恰恰是人工操作最难自查的。

变化点：

- 「既…也…」+「在这样的规模下」——把上文提到的规模与本句的因果关系显式接上
- 破折号改为分号 +「而」——原句的破折号同时承担「解释」与「转折」两种功能，显式化为转折

## 8. 遗留与注意

- **术语表需随内容扩充**。新增章节涉及新术语时，先补 `term.txt` 再跑，否则混元会自行变译。
- **混元温度**：`1.0` 用于正文（保留改写力度），温度更低会更接近直译、改写力度减弱。
- **本流程不适用于表格与图注**。图注是压缩的说明文字，展开会显得啰嗦；表格单元格展开会破坏布局。
- **未提交**：当前改动在工作区，`git checkout -- 最新报告/paper/sections/` 可回退。

## 9. 第二轮：全篇按可读性规则直接改写（2026-11）

第 2–7 节的往返翻译只处理了新增段落。这一轮把整个 `paper/` 正文过了一遍，改法也换成「按显式规则逐段重写」，不再走翻译链路——因为问题已经不在句式翻译，而在**论述顺序**与**句间连接**。

### 9.1 三条硬规则

1. **禁止「标签 + 句号」起段**。`背景。这份想定……`、`失效模式。有两处。`、`其一，数据版本。本节……` 这类写法一律展开成完整主谓句：`要判断人机协同是否必要，可以先看这份想定给人留下了多大的工作量。`
   - 例外：确有信息量的分论点总领段可以保留前置，但必须自身成立，例如 `（1）决策：由人给意图，由机器给精度。`
2. **先因后果、先证据后观点**。凡原稿把结论放在段首、理由跟在后面的，一律倒过来写。典型如「比兵力分值更重要的是占领分」→ 先讲兵力分值怎么算、占领分怎么算、各自量级如何，最后落到「因此占领分的意义在于它是确定性最高的得分途径」。
3. **连接词显式化**。段间补「先看／再看／最后是」「正因为如此」「反过来」「换句话说」；句间把破折号承担的因果、转折拆成独立小句。宁可多写半句，也不让读者自己补关系。

### 9.2 范围与不动的部分

- 处理：所有正文段落、列表项的引导句、摘要（`main.typ` 的 `abstract`）。
- 不动：标题、表头与单元格、图注、伪代码、数学式、`@ref`／`<label>`、行内代码、命令与字段名。
- 校验：`@ref` 与 `<label>` 数量逐文件比对无变化；`typst compile` 通过；成品 182 页。

### 9.3 效果

段落数不变（一段仍是一行），字符数增幅约 1%–4%（如 `03-basic.typ` +3.7%、`04-core.typ` +2.5%、`05-perf.typ` +0.9%）。增幅远小于第 6 节的 25%，因为这一轮做的是**语序重排与连接补齐**，而不是把隐含内容全部展开——原稿的信息密度本身已经够，缺的是让读者一次读懂的顺序。

## 10. 作者口径汇总（以此为准）

下面按"问题 → 例子 → 做法"逐条整理。前面 §9 各小节里的口径如有冲突，以本节为准。

### 10.1 句子不能电报化：结论前要先铺事实

**问题**：把一句判断压缩成"比 X 更重要的是 Y"这种短句，读者不知道 X 怎么算、Y 怎么来的。

**例子**
- 原：`比兵力分值更重要的是占领分，其分值量级足以左右胜负结论。`
- 做法：先把两边的账算给人看，最后才落判断——`兵力分值……红方 5449 分、蓝方 5446 分，几乎相等……但占领分三项的单项收益达到 250 分与 400 分，折算成击落交换比相当于 3.6 与 5.7 架苏-35S，因此一次占领分上的进展，收益与击落数架战斗机相当……不过占领分的上限只有 1200 分与 1150 分，远低于摧毁可得的分值，所以它的意义不是量级更大，而是确定性更高。`

**做法**
- 判断句之前，至少给出一个可核对的数或一条可复述的因果。
- 出现"更重要的是""关键在于""本质上是"这类转折时，前面必须已经立好被比较的两项。

### 10.2 不许用"标签 + 句号"起段

**问题**：`背景。` `问题。` `失效模式。` `其一，数据版本。` 这种写法，等于把提纲直接当正文。

**例子**
- 原：`背景。 这份想定的规模可以直接量出来：……`
- 改：`要判断人机协同究竟有没有必要，可以先看这份想定给人留下了多大的工作量。它的规模是可以直接量出来的：……`
- 原：`失效模式。 有两处。`
- 改：`这一环的失效模式有两处。`

**做法**
- 只有确有信息量的分论点总领可以前置，且必须自身是完整句，例如`（1）决策：由人给意图，由机器给精度。`
- 其余标签一律展开成主谓句；`其一/其二` 改为`第一处/第二处 + 具体对象`。

### 10.3 段落之间、句子之间要把连接写出来

**问题**：靠分号、破折号、并列结构隐含因果与转折，读者得自己补关系。

**例子**
- 原：`而这类错误比"跑不起来"更难发现。`
- 改：`而这类错误比"跑不起来"更难发现，因为推演照常推进，只是前提已经不是原本想设的那个战场。`
- 段间要有承接：`先看西段……`／`再看中段……`／`最后是东北方向……`；换轨道时明说：`接下来，才轮到双方各自怎么选。这一步的依据不再是博弈论，而是想定的分值结构。`

**做法**：因果、让步、条件、指代都要落到字面；一段之内如果换了依据来源，必须有一句话交代换轨。

### 10.4 关键名词不能直接蹦出来

**问题**：`判据``真源``包线``交换比``哨点` 这类词第一次出现时不解释，评委读着跳。

**例子**
- `所谓兵力分值，是平台给每个作战单元标定的价值，单元被摧毁时，双方就按这个价值加减分。`
- `所谓判据，是一条能把当前局面映射成"该做还是不该做"的算式或比较。`
- `所谓无头引擎，指的是不带图形界面、只按脚本推进仿真的引擎进程。`

**做法**：术语首次出现给一句解释；解释长就单独成句，短就放在句中（`即……`／`也就是……`）。

### 10.5 解释要会"前置"，不能通篇"先结论、后补解释"

**问题**：1.1 节一开始几乎每段都是"先抛一句判断，后面再跟名词解释"，读多了烦。

**例子**
- 反面：`在这个结构下，鞍点与纳什均衡是同一件事。鞍点指的是这样一组策略……`
- 改后：`要判断这个博弈的均衡落在哪里，先得把两个概念说清。所谓鞍点，是这样一组策略……而在零和博弈里，鞍点恰好也是纳什均衡。所以两者是同一件事。`

**做法**：一段之内最多一处"结论 + 后补解释"；解释内容多时先铺垫再落判断（`要看……先得算清……`／`要判断……先得把……说清`）。

### 10.6 "所谓 X，是……"是首选句式，可以反复用

**问题**：我曾把它当成重复口头禅，把 `所谓判据，是……` 删成 `判据是……`，反而更生硬。

**例子**
- 改坏：`判据是一条能把当前局面映射成……的算式。`
- 正确：`所谓判据，是一条能把当前局面映射成……的算式。`

**做法**：保留引导词；需要变化时换的是解释的位置与后半句的接法（`指的是`／`衡量的是`／`说的就是`），不是删掉"所谓"。

### 10.7 段落要有推理链，不能是知识陈列

**问题**：一段里把几个概念各自解释清楚，再给结论，读者仍看不出"这一步为什么要接下一步"。

**例子**（博弈均衡段）
- 陈列式：`鞍点是什么……纯策略是什么……所以双方该怎么做。` 三句各自成立，但彼此只有"并且"的关系。
- 推演式：`得分相互抵消（局面）→ 这类局面叫零和，好处是不必猜对方偏好（结构）→ 行动公开可见，藏不住，所以只能是确定的一手（约束）→ 于是最优可算：每区只计一次、250 分、需停留 30 分钟，蓝方压向少数区，红方拖住 30 分钟（结论）。`
- 而且要避免元话语：`先得把两个概念说清` 这种"我要开始解释了"的句子是把备课过程写进正文，应从局面本身起句。

**做法**：写之前先列链条，每一步都问"上一步缺了什么，才需要这一步"；概念在被需要时出现，不预先排队。

### 10.8 工作流：先自写 → 再双跳 → 最后精校

**问题**：先跑混元再照译稿改，会连它的段落切分和"首先需要明确两个概念"式的教学腔一起继承下来。

**做法**
1. 按推理链自己写一稿；
2. 把自己的稿子送混元中→日→中，只为把句子撑开、把省略的语法成分补出来；
3. 精校：数字、实体、因果方向一律以自己稿子为准（实测混元会把 `每区只计一次、250 分` 译成 `其价值为 1 分（对应 250 分）`，会把 `$U_B=-U_R$` 与 "红方" 的占位符互换）。

### 10.9 分批交付，与作者并行修改共存

**问题**：论文仍在更新，作者会同时改同一个文件（例如把"这份想定"改成"本想定"）。

**做法**
- 一次只做一个节批次，改完立即编译并汇报；
- 写回用"段首句定位 + 整段替换"，不要按行号；`seg/*.txt` 是抽取快照，改过的段落不再匹配；
- 作者的用词与改动一律不回退、不"纠正"。

### 10.10 术语不要用翻译腔的抽象壳子

**问题**：`个别条款的单项收益` 里的"条款"是 clause 的直译腔，这里说的是占领分的具体项目。

**例子**：改`一次加固或一次支援拿到的分，就足以改变胜负的走向`。

**做法**：`条款`→具体项目；`情形`→局面/这一次；`事项`→具体那一条；`因素`→说明是哪一个量；`维度/层面`→方面，并写明是哪一面。

### 10.11 一批改完要自检的三件事

1. 这一段是不是先给了事实/证据，再给判断（10.1）；
2. 有没有"标签 + 句号"起段、有没有连续两段都用"结论 + 后补解释"（10.2、10.5）；
3. 首次出现的术语是否都解释过，解释位置是否有变化（10.4、10.5、10.6）。

### 10.12 不用"一个事实 / 一处口径 / 一件事情"这类虚指

**问题**：量词加空壳名词，等于什么都没说——什么事实？哪一处口径？

**例子**
- 原：`要判断这一局该怎么打，先得看清一个事实：双方的得分是相互抵消的。`
- 改：`要判断这一局该怎么打，先要看双方的得分是怎么算的：一个单元被摧毁时，攻击方加分、被摧毁方同时减分，双方的得分因此相互抵消。`
- 原：`还要先把一处统计口径定下来。` → 改：`还要先定下对局统计的口径。`
- 原：`两者比较的其实已经不是同一件事。` → 改：`两者比的根本不是同一类成绩。`
- 原：`如果把它们混成一件事` → 改：`如果把它们混为一谈`

**做法**：量词只在真的可数时才用（`三条指标`、`两处失效`、`四个决策域`）；`事实／口径／事情／情况` 前面若没有具体内容，就把它换成内容本身。

### 10.13 指代与限定：本文件里最重要的一条

作者两次强调：**指代不清晰、名词限定不清晰，是最要命的问题**。判断标准只有一条——读者能否只凭**本段前面二十字之内**确定这个词指的是什么；不能，就必须写全。

**（1）代词**
- `它／它们／这／该／此／其／上述／前者／后者／两者` 的先行词必须在同段内、紧邻出现，且只有一个候选。
- 跨段不用代词。上一段说的是"两种失效"，下一段再写"这种失效"就不合格，要写"漏采周期造成的失效"。
- 并列两项用`前者/后者`时，两项必须在同一句里刚列完，中间不夹别的名词。

**（2）限定**
- `这/该 + 抽象名词` 一律补全：`态势这一中间层` → `态势真源这一中间层`；`这一区别` → `两种错误后果上的区别`；`改了两处` → `改了两个变量`。
- `这一层／这是／两种／几处／一件事` 后面必须跟出所指的是什么。
- 句尾不要用`取决于它／建立在它之上`，把名词写回：`取决于构建耗时`。

**（3）审计方法**（每批改完必做）
1. 用正则把全节的 `它|它们|这|该|此|其|上述|前者|后者|两者|这些|其中` 连上下文一起列出来；
2. 逐条问"只凭本段前 20 字，能确定所指吗"；
3. 不能的，改成具体名词；能但读着别扭的，也改成具体名词。

**已修例子**
| 原文 | 改后 |
|---|---|
| `所有规则都是围绕上面这个时间框架设计的` | `围绕上面算出的两个时间窗设计的：蓝方的加固要在 30 分钟内完成，红方的舰船要在 180 分钟内进入并停留` |
| `因此人单独做时，失效发生在产能与可核验性这两处` | `因此人单独做设计时，会同时卡在产能与可核验性上：做得不够快，做完也说不清对不对` |
| `而这一类错误，恰恰是人工操作最难自查的` | `而漏项这一类错误，恰恰是人工操作最难自查的` |
| `参数这一层之所以必须单列` | `阈值参数之所以必须单列` |
| `两者都不经过态势这一中间层` | `两者都不经过态势真源这一中间层` |
| `取决于它` | `取决于构建耗时` |
| `排在它后面的四个决策域` | `排在真源后面的四个决策域` |
| `这里还要承认一件事` | `规则层不学习，不等于规则从不改动；这一点必须说明` |


**问题**：`参数这一层`是什么的参数？`两种失效`是哪两种？读者要回上文找。

**例子**
- `这一层的取舍需要先在这里说清楚` → `阈值参数的取舍需要先在这里说清楚`
- `加上参数这一层之后` → `把参数层也加进来之后`
- `同族派生时同时改了两处` → `同族派生时同时改了两个变量`
- `又让态势受到污染` → `又会让态势刷新受到污染`
- 失效模式段：`这一环的失效模式同样有两种，而且两种失效的方向正好相反`，随后直接点名`第一种来自单向依赖……第二种是收敛过度……`

**做法**：`这一层／这是／两种／几处` 后面必须跟出所指的是什么；不能靠读者回上文对齐。

### 10.14 "所谓"是引导词，不是计数目标

**问题**：一段接一段地"所谓 X，是……"，读起来像词典。但反过来，把"所谓"删干净同样是错：删掉之后 `判据是……` 比 `所谓判据，是……` 更生硬，读者也不知道这是一次术语界定。

**判断标准（不是配额）**
一句话问清：这个词是正文里第一次出现、需要读者停一下的界定对象吗？
- 是 → 用"所谓 X，指的是……"，哪怕同节已经用过几次；
- 否（普通词，或本节已界定过）→ 直接说 `兵力分值指的是……`、`无头引擎是不带图形界面的引擎进程`。

**结论**：一节 1 处和 6 处都可能正确。指标只看"有没有把普通词也套上所谓"，不看总数。

### 10.15 破折号：先判关系，再决定用不用

**问题**：`行动的冲突因此消失——例如两艘舰……` 这类写法里，破折号同时干着解释、举例、转折三件事，读者要自己判断是哪一件。但把它一律换成句号同样会出事，会把"总说"和"解释"拆成两个不相干的句子。

**判断顺序**
1. 后半句是给前半句**做解释、命名或列举** → 首选冒号；句子已经很长、冒号后还有并列成分时，破折号更好读。
2. 后半句是**另一个独立事实** → 句号。
3. 后半句是**同位语**（`也就是／即／包括`）→ 用词，不用标点。
4. 前后是**因果或转折** → 写出连接词（`因为／而／但`），不允许靠破折号暗示。
5. **对比插入**（`A——而 B——`）、**书名与专名内部**（《诺曼底 2027——人机协同版》）→ 保留破折号。

**禁止的只有两种**：用破折号代替连接词让读者猜关系；用破折号省掉主语。
**数量**：一节 0 处和 3 处都正常，按句式判断，不设上限也不设"必须清零"。

### 10.16 双跳是底稿，不是参考稿

**问题**：我按自己的稿子写完，双跳跑完只挑一两处"措辞更好"的地方，其余全按自己的稿子走——等于用我的短句盖掉了它补出的句法，最后留下的还是原来那套腔。

**做法**
- 双跳的输出是**句子骨架**：它把主语重复出来、把分句接成从句、把省略的成分补齐。这些必须照用，除非句子被译错。
- 我只负责改两类东西：**名词**与**数字**。
- 判断标准不是"它的措辞比我的好"，而是"它的句子是不是比我的完整"。若是，就按它的句子重写，把名词换回来。

例子（`只抓一次`段）
- 我的稿：`所谓"只抓一次"，指的是物理作战域三维监控是全系统唯一直接读取仿真内核的单位。它把全量态势结构化之后写入真源，四个决策域与前端小窗都从真源读取，不再各自调用平台接口。`
- 按双跳骨架改：`所谓"只抓一次"，指的是整个系统里只有物理作战域三维监控这一个组件直接读取仿真内核的数据。它把读到的全量态势结构化之后写进态势真源，另外四个组件，也就是四个决策域与前端小窗，都不再去调用平台接口，而是从真源里取数。`

### 10.17 禁止元语言：正文不叙述"我要怎么写"

**问题**：句子的主语是"本文／这一节／这一点"，而不是研究对象。读者想知道的是事情本身，不是作者的写作安排。

**例子**
| 元语言 | 改后（直接说内容） |
|---|---|
| `这一点必须说明，否则"规则层不学习"会被读成"我们不迭代规则"` | `规则层不学习，但规则的结构仍在改动：掉头门限从 50 km 分档改成 $1.2 d_0$、开火门限从固定 60 海里改成 $0.8 d_0$，都是跑完之后看了结果才改的，样本为 1、不可复现` |
| `现状需要说清楚：响应面部分已实现并实测` | `响应面部分已实现并实测` |
| `这条链路里有两个术语要先交代` | 删掉，直接进入定义 |
| `阈值参数的取舍需要先在这里说清楚，因为后文会反复引用它` | `阈值参数与前三方面不同：前三方面都在一次操作里见效，阈值只能在一批对局上迭代` |
| `由此可以确定，下文给出的方案不能是……` | `因此方案不能是……` |
| `要注意这里的主语是蓝方飞机` | `这里的主语是蓝方飞机：……` |

**做法**
- 禁用句式：`需要说明／必须指出／值得注意／这里要说清／先交代／下文／上文／如前所述／不再重复／否则会被读成／读者可能以为`。
- 允许保留的只有结构性指路（`见 @sec:perf 节`、`第 3 章`），且不承担论证。
- 自检：把每句主语列出来，凡是"本文／本节／这一点／下文"作主语的句子，一律改成研究对象作主语。

### 10.18 句子成分不能省：主语与定语

**问题**：状语开头、主语缺失，或者名词没有定语，读者要自己找"谁"和"哪一个"。

**例子**
- 原：`把四个方面合起来，共同的结构可以概括为一句话——"人定方向、机守精度"。`
- 问题：`共同的结构`是谁的共同结构？整句没有主语。
- 改：`这四个方面有一个共同的结构：方向由人定，精度由机器守，也就是"人定方向、机守精度"。`
- 原：`把参数层也加进来之后，结论还要再补半句`（"结论"是元语言，"补半句"是在说文章）
- 改：`参数层加进来之后，这句话还要往前延伸一步，因为方向里也包括"什么算好"。`

**做法**
- 每句都要能回答"谁做了什么"；状语（`把……／在……／对于……`）不能代替主语。
- 名词前缺定语时，用本段已有的名词补上（`这四个方面的共同结构`、`阈值参数的取舍`、`态势真源的写入周期`）。
- 口号式短语（`人定方向、机守精度`）第一次出现必须当场解释，不能直接甩出来当结论。

### 10.19 机械层指标是体检表，不是施工图

**问题（本节记录的教训，2026-11）**：把"破折号≈0、所谓≤5"当成了施工目标，逐条正则匹配、见到就换，结果改坏了两处句子：

| 位置 | 改坏的版本 | 病因 |
|---|---|---|
| 6 章开头 | `三样东西分别回答同一个问题在不同层次上的版本：改了阈值之后……` | 原句是"回答同一个问题——改了阈值之后……"，破折号后的内容是"问题"的具体内容，换成句号后它悬空了，只剩一个残句 |
| 1.1 计分机制 | `这正是想定设计者想要的效果。红方以海空优势打击……` | 后半句在解释"这个效果"是什么，是同位语式的展开，拆成句号后两句话失去主从关系 |

**做法**
- 正则只能用来**列出候选**，不能用来**下刀**：每一条都要回到句子问"后半句和前半句是什么关系"。
- 改完必须重读整段，检查有没有出现无主语的残句、悬空的"这／它"、被拆散的总分结构。
- 指标口径同步修正：正文破折号不设上限（只禁止代连接、代主语），所谓不设"必须清零"。
- 判断标准始终是**读者能不能一次读懂**，不是计数器归零。
