# 低空导弹二态按钮（人类意图层）

一个按钮把地导单元在**打击模式**（停车、开雷达、等目标进 0.6·Dmax 发弹）与
**前进模式**（正北机动、全速 50 km/h、关雷达、不交战）之间切换。人只决定
"暴露还是隐蔽"，机器负责把它展开成一串平台动作，并把**每一次点击的往返时延**
落到文件里。

- 上位条令不变：受到攻击时忽略电磁管控 = 否、自由开火、自动规避 = 否。
- 本目录只做**人类意图层**：不发弹、不选目标、不改条令。
- 纯标准库 + 平台自带库，Python 3.9 兼容，无新依赖。

设计依据见同目录 [`design.md`](design.md)（二态语义、为何人只该决定暴露/隐蔽、
与设计报告 1.3 节「意图—执行」环的对应、验收指标）。

## 1. 文件清单

| 文件 | 跑在哪 | 职责 |
| --- | --- | --- |
| `pi_listener.py` | **推演进程内**（客户端「智能体编辑」导入，类名 `Agent`） | 每决策周期从命令文件尾部读新行 → 按 `seq` 幂等执行 → 转译成平台动作 → 写回执 |
| `pi_button_server.py` | 独立进程（纯标准库 `http.server`） | `GET /` 二态按钮页面；`POST /press` 写一行命令；`GET /acks` 读最近 N 条回执 |
| `operator_sim.py` | 离线（不需要平台、不需要 Windows） | 脚本化操作员：按 `schedule.json` 的仿真时刻写命令，记录按下墙钟，统计往返时延 P50/P95 |
| `README.md` | — | 本文：部署、协议、实验方法、统计口径、风险 |
| `design.md` | — | 一页纸设计说明与验收指标 |

数据流（三个进程，两条文件通道，互不共用网络连接）：

```
浏览器页面  ──POST /press──▶  pi_button_server ──写──▶ cmd.jsonl
                                                        │（只读增量）
        operator_sim ──按仿真时刻写────────────────────▶ │
                                                        ▼
                                               pi_listener（推演进程内）
                                                        │ 平台指令（与战术智能体共用通道）
                                                        ▼
                                                  灵弈推演内核
                                                        │
                                              ack.jsonl ◀┘（每次点击一行）
                                     ▲                  ▲
                          页面 GET /acks        operator_sim 读
```

## 2. 二态语义（谁下发什么）

| | 打击模式 `strike` | 前进模式 `move` |
| --- | --- | --- |
| 航路 | `clear_plotted_course()` 先清 | `plotted_course([正北 50 km])` |
| 阵位 | `hold_positon(True)` | `hold_positon(False)` |
| 速度/油门 | `set_desired_speed(0)` + `Throttle.FullStop` | `Throttle.Full` + `set_desired_speed(50)` |
| 雷达 | `doctrine_switch_radar(True)` + `switch_radar(True)` | 同上两个，参数 `False`（先关再走） |
| 交战 | 由平台按"自由开火 + 雷达开"执行，0.6·Dmax 只进回执备注 | 雷达关，无目标可打 |
| 暴露 | 高（辐射 + 静止） | 低（静默 + 移动） |

两个顺序是**实测结论**，不是风格问题：

1. **先清航路再停车**。只停油门不清航路，单元会继续朝旧航路点跑
   （`SamBattalionDefense._recover` 的注释记录了这条）。
2. **停车与开雷达同一次下发**。只停不开等于瞎停，只开不停等于边跑边辐射。

另外首次切换会补一条 `EMCON_Obey_doctrine(False)`（每单元一次，可用
`EMCON_RELEASE = False` 关掉）：平台可能因任务条令/电磁管控把雷达改回相反状态，
而本地缓存仍记着旧值——这是 `SamBattalionDefense` 里记过的"停了但雷达没开"。
**这一条是否必要，在靶机上未验证**（见 §8）。

## 3. 靶机上跑起来（3 步，命令级）

> 前置：推演本身要在 **Session 1**（已登录的交互桌面）里跑，SSH 直连是 Session 0，
> `Plat.exe` 会秒退（《灵弈使用与批量对局指南》§4.3）。页面服务是纯 HTTP，
> 放哪个会话都行。

**① 拷文件**（三份 .py 放进客户端的智能体目录，和 `monitor-agent\` 同一层）

```bat
mkdir D:\LingYi\intelligent\ai\agent\button
copy /Y pi_listener.py pi_button_server.py operator_sim.py D:\LingYi\intelligent\ai\agent\button\
```

**② 起页面服务**（平台自带 Python 3.9.19；也可以先在 SSH 里起，它不碰引擎）

```bat
D:\LingYi\intelligent\new_env\ray210\python.exe ^
  D:\LingYi\intelligent\ai\agent\button\pi_button_server.py --port 8764
:: 浏览器打开 http://127.0.0.1:8764/
:: 命令行也能点一下：curl -X POST -d "{\"action\":\"strike\"}" http://127.0.0.1:8764/press
```

**③ 客户端挂监听智能体**

1. **智能体调度 → 智能体编辑 → 左下角「＋」** 选
   `ai\agent\button\pi_listener.py`，出现 `Agent`；
2. 右上方 **＋「决策脚本输入框」** 把受控单元加进去（**实体单元**：`捷羚地空导弹排#1`
   等；不加进去平台不会让它控制这些单元）；
3. 点该智能体的**启动**，然后 **推演 → 推演速度** 开始推演。

验收（看三个地方）：

| 看什么 | 期望 |
| --- | --- |
| 智能体日志（stderr / `logs\simulate.log`） | `[按钮监听] 初始化完成：{'受控单元': [...], 'Dmax': {...}}`；每次点击一行 `点击 seq=1 strike [...] → 成功（时延 590 ms = 排队 540 + 转译 50...）` |
| 客户端「智能体消息输出」（`Logs\agentMsg.log`） | `【按钮】监听就绪：…`、`【按钮】seq1 … → strike模式（590 ms，7 条指令）` |
| `D:\LingYi\exp\button\ack.jsonl` | 每次点击一行 JSON；页面下方表格同一份数据 |

**④ 必做的前置（否则测不到东西）**：主智能体的地导自卫规则要**关掉**——
`SamBattalionDefense.ENABLE = False`（或该模块不挂）。否则它和本智能体同时写
同一个单元的雷达/油门/航路，两边互相覆盖，时延与暴露时长都不可信。

环境变量在**客户端进程**里生效（智能体是客户端 spawn 的子进程），默认值已按草图
设好，不改也能跑；要改就设系统环境变量后重启客户端。

## 4. 通道协议

### 4.1 命令文件 `cmd.jsonl`（页面服务 / operator_sim 写，监听智能体读）

```json
{"seq":1,"t_wall":1794930000.12,"action":"strike","unit":"捷羚地空导弹排#1"}
```

| 字段 | 说明 |
| --- | --- |
| `seq` | 单调递增，**唯一的幂等键**；重复 `seq` 只执行一次。页面服务与 operator_sim 都按文件里已有的最大 `seq` 续号，不会撞号 |
| `t_wall` | 按下瞬间的墙钟（`time.time()`），时延的起点 |
| `action` | `strike` 或 `move`，其它值进回执 `ok:false` |
| `unit` | 单元名或名称片段；`""` / `"*"` = 关键字匹配到的**全部**地导单元 |

### 4.2 回执文件 `ack.jsonl`（监听智能体写）

```json
{"seq":1,"t_wall_press":1794930000.12,"t_wall_ack":1794930000.71,
 "latency_ms":590.4,"sim_t":1210.0,
 "orders":["捷羚地空导弹排#1 clear_plotted_course()",
           "捷羚地空导弹排#1 hold_positon(True)", "..."],
 "unit":["捷羚地空导弹排#1"],"action":"strike","ok":true,
 "note":"最近空中目标42km ≤发弹线44km","wait_ms":540.0,"apply_ms":50.4}
```

| 字段 | 含义 |
| --- | --- |
| `latency_ms` | `t_wall_ack - t_wall_press`：**往返时延**（含排队） |
| `wait_ms` | 按下 → 被下一个决策周期取走（排队，下限 = 一个决策间隔） |
| `apply_ms` | 转译 + 下发本身的开销（`latency_ms = wait_ms + apply_ms`） |
| `sim_t` | 回执那一刻的推演时刻（秒），用来画"暴露时长"时间轴 |
| `orders` | **逐条**平台指令，`len(orders)` = 这次点击等于多少条手工指令 |
| `note` | 只读提示：0.6·Dmax 与最近空中目标；或失败原因（含候选单元名） |

监听智能体侧的三条保证：读到的必须是**完整行**（写到一半的行留到下个周期）、
`seq` 幂等（含跨文件截断/轮转）、**任何异常只告警不中断推演**（`step` 全体 try/except）。

## 6. 无人值守的时延实验（`operator_sim.py`）

### 6.1 用例文件 `schedule.json`

```json
[{"t_sim": 1200, "action": "move"},
 {"t_sim": 1500, "action": "strike", "unit": "捷羚地空导弹排#1"},
 {"t_sim": 1800, "action": "move"},
 {"t_sim": 2100, "action": "strike"}]
```

`t_sim` 是**推演时间**（秒）；`unit` 省略则用 `--unit`/全部地导单元。

### 6.2 跑

```bat
:: 先开始推演（页面服务与监听智能体都已就位），再起操作员
D:\LingYi\intelligent\new_env\ray210\python.exe ^
  D:\LingYi\intelligent\ai\agent\button\operator_sim.py --schedule schedule.json --speed 10
```

- `--speed` 必须等于当前推演倍速（10 倍速 = 每墙钟秒 10 推演秒）。
- **锚点**：脚本先等第一条回执，用它的 `(sim_t, t_wall_ack)` 把"推演时间"和
  "墙钟时间"对上，再按 `--speed` 排程。所以它必须**在对局开始后、第一次点击之前**
  起来。对局已在中途就用 `--anchor-sim 600`（= 现在这一刻的推演时刻）。
- `--dry-run` 只打印计划，不写任何文件（可以先在开发机上验证 schedule 格式）。
- 输出：`presses.jsonl`（每次按下：`seq/action/unit/t_sim/t_wall_press`），终端最后
  打印逐条时延与 `n / P50 / P95 / max / 未回执条数`。

### 6.3 怎么念这个数

```
往返时延 = 排队（等一个决策周期）+ 转译下发
排队下限 = 决策间隔 / 倍速 = 5 s / 10 = 500 ms
```

所以 10 倍速下 **P50 落在 500~700 ms 是正常**（等于"零排队"），明显高出的部分才是
链路本身的开销；要压低排队就把决策间隔调小（比赛允许的最小值是 5 推演秒）。
`ack.jsonl` 里的 `wait_ms` / `apply_ms` 已经把这两部分分开记好了。

## 7. 操作量：一次按钮 vs 逐条手工指令

同一件事（把一个地导单元从"前进"切到"打击"）在客户端界面上要逐项点：清航路 →
停车（油门 + 速度）→ 保持阵位 → 条令电磁管控开雷达 → 传感器开雷达，**6~7 次点选**；
按钮是 **1 次点击**。统计口径：

| 量 | 怎么拿 |
| --- | --- |
| 按钮点击次数 | `ack.jsonl` 行数（= 人按了几次） |
| 按钮实际下发的指令条数 | 每行 `len(orders)` 之和 |
| 节省比 | `1 - 点击数 / 指令条数`（例：6 次点击 / 42 条指令 → 86% 的点选被省掉） |
| 人工逐条的操作耗时 | 录屏或秒表实测（**未验证**，需现场取 3~5 个样本）；与 `latency_ms` 对比即得时间节省 |

注意这两类操作**共用**平台的 500 条/10 秒配额，所以按钮必须去重（页面 500 ms 合并）
且一次点击只下发一次——这正是"封装成按钮而不开放自由输入"的理由。

## 8. 风险与限制

### 8.1 未验证（靶机上必须逐条确认）

| # | 事项 | 怎么确认 |
| --- | --- | --- |
| 1 | `EMCON_Obey_doctrine(False)` 是否必需，以及它是否抵掉"受到攻击时忽略电磁管控 = 否"这条上位条令 | 看雷达实际状态（客户端单元面板/`Plat#LuaHistory.log`）；不行就设 `PI_EMCON_RELEASE=0` 再跑 |
| 2 | `switch_radar` / `doctrine_switch_radar` 在**地面单元**上是否都吃得下（两个都下发是双保险，不报错就算过） | 回执 `orders` 里不带 `(失败:…)` 即成功；平台的 `(无此接口)` 会在日志里点名 |
| 3 | 前进模式 `hold_positon(False) + plotted_course` 在**设施类地面单元**上是否真能移动（设施可能不可动） | 看单元位置变化；若不可动，前进模式的语义退化为"关机静默"（此时报告里要写清） |
| 4 | 与该智能体并行挂的**战术智能体**是否真被关掉（`SamBattalionDefense.ENABLE=False`） | 日志里不应出现 `[地空导弹营]` 的雷达/规避动作与本智能体的 `[按钮监听]` 交替刷 |
| 5 | 客户端「智能体编辑」能否从 `ai\agent\button\` 子目录导入（与 monitor-agent 同款部署方式） | 导入不出 `Agent` 就把三个 .py 平铺到 `ai\agent\` 再试 |
| 6 | 决策脚本输入框必须把受控单元加进去，否则指令被忽略 | 不加时回执 `ok:false` 或平台回"找不到单元" |
| 7 | 单条指令 300 字符上限对本链路无影响（最长一条是 1 个航路点） | 若超长，`Plat#LuaHistory.log` 会显示"已被取消下发" |

### 8.2 已知限制（设计取舍，不是 bug）

1. **时延下限 = 一个决策间隔**。读命令与下发都在 `step` 线程里做（与其他智能体
   共用发送通道，另起线程有抢占风险，未验证），所以 10 倍速下 ≥ 0.5 墙钟秒。
   设计报告 1.3 节写的是"监听智能体持有独立工作线程"——本实现**没有**那样做，
   这是偏保守的一步，若实测时延不可接受再评估（见 `design.md` §4）。
2. **回执只证明"指令已下发"，不证明"平台已执行"**。生效与否要看
   `Logs\#LOCAL\Plat#LuaHistory.log`、单元面板或录像。`ok:true` 的含义是"所有
   API 调用都没抛异常/没返回失败"。
3. **不判断谁在打谁**。前进模式下关雷达只是"看不见"，敌方的弹照样能命中；
   本模块不评估威胁，也不自动切回打击模式（草图里"自动规避 = 否"）。
4. **文件通道是单机假设**。两个进程必须在同一台机器上（`D:/LingYi/exp/button/`）；
   跨机要用共享盘或另写 socket。
5. **不做乱序与背压控制**。命令按文件顺序执行；一次积压几十条点击时，每条都要
   等下一个周期，时延会线性变长（这也是"重复点击合并"存在的原因）。
6. **Dmax 反查可能失败**。查不到就不给发弹线提示（回执 `note` 里写"发弹线未知"）
   并把真实挂载打进日志——本文件**不按名称兜底**，避免第二种写死。

## 9. 排错速查

| 现象 | 先看哪 |
| --- | --- |
| 页面点下去没反应 | `pi_button_server.py` 控制台有没有 `POST /press` 行；命令文件是否增长 |
| 命令文件在长、回执不出现 | 监听智能体日志：`未解析到受控单元`（附候选名）？`初始化完成` 的 Dmax 表？ |
| 回执 `ok:false` | `note` 里直接写了原因（未知 action / 未匹配单元 + 候选名） |
| 指令下发成功但单元没动 | `Logs\#LOCAL\Plat#LuaHistory.log` 搜该单元名；地面设施可能不可动（§8.1 #3） |
| 时延大得离谱 | 是否 10 倍速？（`--speed` 报错会整体平移）；`wait_ms` 大还是 `apply_ms` 大 |
| 指令数掉包 | 500 条/10 秒窗口：本链路一次点击 ~7 条，别处超配额时平台回"已被取消下发"（不进本模块的回执，只在 `LuaHistory` 里） |
