# 数据字典（实验v2）

> 适用对象：`实验v2/` 下的两份原始数据——每局一行 `runs.jsonl`，每决策周期一行 `tap/<arm>__<side>.jsonl`。
> 编写日期：2026-11-18。字段来源为**实测样例**（`实验v2/tap_sample/`）；样例未覆盖的字段一律标注"样例未出现"。
> 与 `实验设计.md` 的对应关系：本文定义**字段**，设计文档 §5 定义**指标**。指标必须由本文的字段按给定公式算出，不得引入外部量。

## 1. 通用约定

| 约定 | 说明 |
| --- | --- |
| 编码 | UTF-8（无 BOM），中文不转义（样例中直接是汉字，如 `"红方"`） |
| 格式 | JSON Lines：**一行一个完整 JSON 对象**，行内不换行；对象键顺序固定但**不得依赖顺序**解析 |
| 数值类型 | 浮点统一带小数点（`269.0`、`0.0`），整数不带（`i: 137`、`steps: 136`）。解析端一律按数值转换，不要按字符串比较 |
| 缺失值 | 只出现 `null`（样例：`"cts": null`），**不出现**空字符串、`NaN`、`-` |
| 列表而非字典 | `own` / `cts` 是**位置数组**，不是对象。位置即语义（§3.2、§3.3）；平台未来若插入新列会破坏解析，必须校验长度 |
| 追加写 | 两个文件都是**追加写**。重试会追加新的段（§7.1），不会覆盖旧行 |

### 1.1 单位总表

| 量 | 字段 | 单位 | 取值域 / 说明 |
| --- | --- | --- | --- |
| 仿真时间 | `t` | **秒**（仿真时间轴，原点 = 想定 2027-05-21 04:00:00） | 0 – 10 800（满时长） |
| 采样序号 | `i` | 无量纲 | 1 起，**重试后归零**（§7.1） |
| 墙钟 | `wall` | **Unix epoch 秒**（浮点，带小数） | 例 `1794930723.12` = 2026-11-17 23:52:03.12（UTC+8） |
| 墙钟时长 | `wall_s` | **秒**（相对量） | 整局，含冷启动 |
| 单步墙钟 | `step_avg_s` | **秒** | 步进阶段均值；`step_avg_s × steps ≪ wall_s`（差额 ≈ 45 s，见 §7.6） |
| 经纬度 | `lat` / `lon` | **十进制度**（WGS84） | 样例实测：`lat` 43.66–55.66，`lon` −14.92–8.17（诺曼底战区及其西侧外海） |
| 高度/深度 | `alt` | **米** | **可为负**（水下：样例潜艇 −20 m、−154 m） |
| 速度 | `speed` | **km/h** | ≥0；0 = 静止/停放（样例开局 126 个单元中仅 42 个 >0） |
| 航向 | `heading` | **度** | 0–360（样例实测最小 0.0、最大 360.0）；正北为 0（也写作 360），顺时针 |
| 毁伤 | `damage` | **百分比** | 0–100；样例**全为 0**（§7.4） |
| 得分 | `score` / `red_score` / `blue_score` | **分** | 可为负；平台零和（§7.5） |
| 步数 | `steps` | 步 | 一局内的决策步数（非采样数） |

## 2. `runs.jsonl`：逐字段

一行 = 一局（或一次失败尝试）。官方样例（1 行）：

```json
{"ts": "2026-11-17 23:50:23", "arm": "T1", "theta": "{}", "scenario": "诺曼底2027(人机协同-人人版)_有红有蓝", "episode": 1, "decision_interval": 30, "reset": 1, "finished": true, "steps": 136, "wall_s": 128.2, "step_avg_s": 0.6122, "ok": true, "red_score": 269, "blue_score": -269, "winner": 1, "sim_end": 4050.3, "error_side": ""}
```

| 字段 | 类型 | 单位 | 含义 | 审计用法 / 注意 |
| --- | --- | --- | --- | --- |
| `ts` | string | — | 本局**启动**时刻，格式 `YYYY-MM-DD HH:MM:SS`（靶机本地时钟，UTC+8） | 与 `tap.wall` 对账可量出冷启动（§7.6）；**不是**首采样时刻 |
| `arm` | string | — | 实验臂标签。样例为 `T1`（**探测运行，不属于 13 臂**） | 分组主键；必须与 tap 文件名 `<tag>` 一致 |
| `theta` | string | — | θ 的 JSON **文本**（不是对象），样例 `"{}"` | 与靶机上 `PI_THETA` 逐字比对；不一致说明该局口径污染 |
| `tap` | string | — | 该局采样文件的前缀 `<arm>__<ts>`（如 `A0_new__1794930962`） | **唯一键**：`runs.tap` + `__红方/__蓝方.jsonl` = 采样文件名 |
| `scenario` | string | — | 想定名，**不带 `.scen`** | 必须恒等于 §0 想定名；不等则整批作废 |
| `episode` | int | — | 局号 | **实测快照 4 局全部为 `1`**（批处理每局重启进程、不递增），因此**不能当唯一键**；唯一键是 `tap`。与 `tap.ep` 对应 |
| `decision_interval` | int | 仿真秒 | 决策间隔，本实验恒 30 | 与 `t` 的增量（≈30）互校 |
| `reset` | int | — | `Deduction.reset(ep)` 返回码：`1` 成功；`-1` 推演服务连接失败；`-2` 无想定；`-3` 无初始态势 | `!= 1` 的局**不是实验局**，必须单列，不得计入分母 |
| `finished` | bool | — | 框架认为本局正常结束（`is_done()` 为真） | 与 `ok` 交叉：`finished=true, ok=false` = 结局取到了但结果被判无效 |
| `steps` | int | 步 | 决策步数 | 满时长局 ≈361；早停局按比例（样例 136） |
| `wall_s` | float | 秒 | 整局墙钟（进程内从 reset 到取结果） | 预算核算；**含 45 s 冷启动** |
| `step_avg_s` | float | 秒 | 步进阶段单步均值 | `step_avg_s × steps ≈ wall_s − 44.6 s`（4 局复核：44.68 / 44.75 / 44.70 / 44.38 s）；**不要**用 `wall_s/steps` 代替它 |
| `ok` | bool | — | 该局是否计入本臂的有效样本 | 失败/超时/异常局应 `false` 且**保留整行**（§7.2） |
| `red_score` | float | 分 | 红方总分（平台 `BatResult`） | 主结局；与 `blue_score` 之和恒为 0 |
| `blue_score` | float | 分 | 蓝方总分 | 零和校验：`abs(red+blue) < 1e-6` |
| `winner` | int | — | `bat_result`：`1` 红胜 / `-1` 蓝胜 / `0` 平 | 应满足 `sign(red_score)==winner`（0 分处的浮点边界除外） |
| `sim_end` | float | 仿真秒 | 结束时的仿真时刻 | 满时长 = 10 800；实测早停 3 164.3 / 4 339.3 / 4 050.3（§7.3） |
| `error_side` | string | — | 出错方；空串 = 无错误 | 非空时该局不可用于比较，且要记入失败率 |

**样例未出现但设计需要的字段**（必须在实现时补，否则 §7.2 的删失审计无法做）：`attempt`（第几次尝试）、`timeout`（是否被 600 s 截断）、`tap_path`（该局采样文件路径）。

## 3. `tap/<arm>__<side>.jsonl`：逐字段

一行 = 一个决策周期的态势真源快照（`pi_tap` 只读，不下发指令）。

### 3.1 顶层字段

| 字段 | 类型 | 单位 | 含义 | 注意 |
| --- | --- | --- | --- | --- |
| `tag` | string | — | 实验臂标签 | 与 `runs.arm` 相同；文件内恒为同一值 |
| `side` | string | — | `"红方"` / `"蓝方"` | 与文件名 `<side>` 相同；文件内恒为同一值 |
| `ep` | int | — | 局号 | 与 `runs.episode` 相同 |
| `i` | int | — | 采样序号，1 起 | **重试后归零**（§7.1）；不能当唯一键 |
| `t` | float | 仿真秒 | 采样时刻 | 段内严格递增；首点恒 0；相邻间隔≈30 s（实测 20–41 s，均值 30.00），段内首个间隔可短至 0.3 s |
| `score` | float | 分 | **本方**当前得分 | 红方文件终值 = `runs.red_score`（样例 269.0 ✓） |
| `own` | array | — | 本方单元列表（只含**存活**单元） | 长度随损失单调下降（样例 126→102） |
| `cts` | array / null | — | 本方**情报**可见的接触列表 | **隔步采集**：奇数步有值、偶数步为 `null`（实测严格交替，快照 181/362 行、样例 106/214 行为 `null`）。`null` = **本步未采集**，**不是**"没有敌人" |
| `wall` | float | epoch 秒 | 采样时刻墙钟 | 用于与 `runs.ts`/日志对齐；**不能**用来反推整局墙钟（§7.6） |

### 3.2 `own[]`：8 元位置数组

```
[name, category, lat, lon, alt, speed, heading, damage]
```

| 位置 | 类型 | 单位 | 含义 | 样例值 |
| --- | --- | --- | --- | --- |
| 0 | string | — | 单元名（含平台 `#编号`），例 `"TB2 无人机#14"` | 注意空格不一（`"TB2 无人机 #15"` vs `"TB2 无人机#14"`），**不要**依赖字符串相等做键 |
| 1 | string | — | 域，三值：`air` / `sea` / `land` | `"air"` |
| 2 | float | 度 | 纬度 | `49.62353` |
| 3 | float | 度 | 经度 | `-1.26787` |
| 4 | float | m | 高度（水下为负） | `6858.0` |
| 5 | float | km/h | 速度 | `130.0` |
| 6 | float | 度 | 航向（0–360，正北 0 顺时针） | `197.2` |
| 7 | float | % | 毁伤百分比 | `0.0`（样例恒 0，§7.4） |

**关键性质**：`own` 只含**存活**单元，被击毁的单元直接从列表消失，不保留"damage=100"的行。因此"存活率"只能按**计数差**算，不能按 `damage` 阈值筛。

### 3.3 `cts[]`：7 元位置数组

```
[name, type_code, lat, lon, alt, speed, heading]
```

| 位置 | 类型 | 单位 | 含义 | 样例值 |
| --- | --- | --- | --- | --- |
| 0 | string | — | 接触名。**部分已识别型别**（`"地空导弹连 (霍克导弹 [P3, TAS]) #33"`），部分仅匿名批号（`"空中 #39"`） | `"奥尔良机场"` |
| 1 | int | — | 平台**类型码**（见下表） | `7` |
| 2 | float | 度 | 纬度 | `48.6961` |
| 3 | float | 度 | 经度 | `1.75984` |
| 4 | float | m | 高度（水下为负） | `117.0` |
| 5 | float | km/h | 速度 | `0.0` |
| 6 | float | 度 | 航向 | `0.0` |

**类型码实测取值**（在样例 214 行中 108 个非空 `cts` 行上统计；官方枚举文档未核对 → 【未验证】映射名称）：

| `type_code` | 观测到的名称样例 | 条目出现次数（214 行） | 不同名称数 | 推定含义 |
| --- | --- | --- | --- | --- |
| 0 | `空中 #39`、`E-2D型"先进鹰眼"舰载预警机 #243` | 1 736 | 87 | 空中目标 |
| 1 | `防空导弹#34`、`防空导弹#35` | 379 | 141 | 在飞弹药（对本方而言是来袭弹） |
| 2 | `水面#85`、`水面#95` | 145 | 4 | 水面舰艇 |
| 3 | `潜艇#24` | 106 | 1 | 潜艇 |
| 7 | `奥尔良机场`、`雷达 (AN/FPS-115型"铺路爪"预警雷达系统)` | 450 | 5 | 固定设施 |
| 8 | `移动设施#33` | 1 968 | 80 | 移动设施/地面机动目标 |
| 17 | `声呐浮标 #217` | 17 | 1 | 声呐浮标（一次性器材） |

两个计数必须分开看：**条目出现次数**（同一批号在多个采样周期重复出现会重复计数）与**不同名称数**（近似实体数）。上表同时给出两者，正是为了说明"接触条数"不能当作"敌情规模"使用。

**三条必须知道的不对称性**：

1. `own` 用**三值域字符串**（air/sea/land），`cts` 用**整数类型码**。两者**不能按同一键连接**。
2. `cts` 是匿名批号，**没有稳定实体键**；同名在不同时刻出现是否同一实体【未验证】（批号可能被复用）。因此**敌方的损失不能从 `cts` 精确统计**，只能给"接触数峰值/均值"这类强度代理。
3. `cts` 本身不含 `damage`，但**敌方毁伤可从对侧 tap 取**：蓝方 tap 的 `own` 里是蓝方单元及其 `damage`（快照实测 0–87.5%）。因此"敌方毁伤"只能来自**对侧 `own`**，不能来自本方 `cts`。

## 4. 两条真实样例

### 4.1 样例 A：`runs.jsonl` 完整一行

来源：`实验v2/tap_sample/runs_sample.jsonl` 第 1 行（文件仅此 1 行）。

```json
{"ts": "2026-11-17 23:50:23", "arm": "T1", "theta": "{}", "scenario": "诺曼底2027(人机协同-人人版)_有红有蓝", "episode": 1, "decision_interval": 30, "reset": 1, "finished": true, "steps": 136, "wall_s": 128.2, "step_avg_s": 0.6122, "ok": true, "red_score": 269, "blue_score": -269, "winner": 1, "sim_end": 4050.3, "error_side": ""}
```

读法：这是**探测臂 T1**（不是 13 臂之一）的第 1 局，θ 为空（全取默认），想定正确载入（`reset=1`），正常结束但**早停**（`sim_end=4050.3` 而非 10 800），136 步、整局 128.2 s、步均 0.6122 s；红方 269 分、蓝方 −269 分（严格零和）、`winner=1`（红胜），无错误。

### 4.2 样例 B：`tap` 一行（**截断展示**）

来源：`实验v2/tap_sample/T1__红方.jsonl` **第 214 行**（文件最后一行），原始行长 **10 363 字节**。
为便于阅读，下面 `own` 只保留**前 2 项**、`cts` 只保留**前 3 项**，其余用 `…` 表示；`…` 之外的文本与原文逐字一致（含空格）。

```json
{"tag": "T1", "side": "红方", "ep": 1, "i": 137, "t": 4050.3, "score": 269.0, "own": [["苏-34 轰炸机 #1", "air", 50.1204, 1.34292, 10973.0, 1704.0, 99.4, 0.0], ["TB2 无人机#14", "air", 49.62353, -1.26787, 6858.0, 130.0, 197.2, 0.0], …], "cts": [["奥尔良机场", 7, 48.6961, 1.75984, 117.0, 0.0, 0.0], ["阿斯图机场", 7, 43.65771, -0.21532, 16.0, 0.0, 0.0], ["单实体机场 (1X 1401-2000M 跑道)", 7, 49.69307, 0.90752, 160.0, 0.0, 0.0], …], "wall": 1794930723.12}
```

原始行末 6 项（`…` 的真实结尾，用于核对是否取到同一行）：

```json
…, ["E-2D型“先进鹰眼”舰载预警机 #243", 0, 46.70273, -12.83898, 9144.0, 370.0, 265.6], ["空中 #245", 0, 48.07855, -11.56857, 10973.0, 648.0, 252.5]], "wall": 1794930723.12}
```

读法：`t=4050.3` 是终局采样，`score=269.0` 与样例 A 的 `red_score` 一致（质检断言 6 就靠这条对上）；`own` 此时有 102 个单元（air 56 / sea 19 / land 27），比开局的 126（80/19/27）少 24 个——即红方在 4 050 s 内损失了 24 架航空器、未损失舰船与地面单元；`cts` 有 50 批接触，其中机场类（`type_code=7`）为固定设施、`#243` 为已识别的蓝方预警机。

### 4.3 两条例外样例（同样是真实数据，必须能解析）

**① `cts = null`**（来源：同文件第 **79** 行，`i=2`，行长 8 508 B）：

```json
{"tag": "T1", "side": "红方", "ep": 1, "i": 2, "t": 0.3, "score": 0.0, "own": [["苏-34 轰炸机 #1", "air", 50.57222, -3.64239, …], …], "cts": null, "wall": 1794930657.88}
```

读法：`null` = **该步未采集情报**（`pi_tap` 隔步采集，实测严格奇数步有值、偶数步为 null）。因此：① 统计"接触数"时把 `null` 当缺失（不是 0）；② 有效采样点数 ≈ 行数/2；③ "在飞弹峰值/均值"只在非 `null` 行上统计。

**② 重试导致 `i`/`t` 归零**（来源：同文件第 **77** 行与第 **78** 行相邻）：

```json
{"tag": "T1", "side": "红方", "ep": 1, "i": 77, "t": 2247.3, "score": 1091.0, …}   ← 第一次尝试的最后一帧（此后中断）
{"tag": "T1", "side": "红方", "ep": 1, "i": 1,  "t": 0.0,    "score": 0.0,    …}   ← 重试后的第一帧（序号归零）
```

读法：同一 `(tag, side, ep)` 下出现 `i` 回退，说明**这一局被重跑过**。第一次尝试在 t=2 247.3 s、得分 1 091 时中断（`runs.jsonl` 只记录最终成功的那次）。分析脚本必须按"段"切分（§7.1）。

## 5. 由字段派生的指标（与设计文档 §5 一一对应）

| 指标 | 公式（字段级） | 单位 | 备注 |
| --- | --- | --- | --- |
| 得分速率 | `red_score / (sim_end/3600)` | 分/h | 主结局；早停使原始分不可比（设计文档 §5.1） |
| 胜负 | `winner` | — | 与 `sign(red_score)` 互校 |
| 航空器存活率 | `count(own.category=="air")[段末] / count(...)[段首]` | — | 含地面停放单元（样例开局 air 80 个，仅 26 个 `speed>0`）；"在空存活率"应按 `speed` 阈值过滤，**禁用 `alt>0`**（停机坪飞机 `alt` 为机场标高） |
| 舰船存活率 | 同上，`category=="sea"` | — | 样例 19/19 |
| 平均毁伤 | `mean(own[][7])` | % | **红方恒 0，不可用于红方**（4 局快照与样例均为 0）；**蓝方 `own` 有 0–87.5** → 作"敌方毁伤"时必须取**对侧** `own`（§7.4） |
| 在飞来袭弹峰值 | `max_t count(cts[][1]==1)` | 枚 | 只含"本方可见的来袭弹"，不含本方发射的弹；**只在非 `null` 的 `cts` 行上统计**（隔步采集） |
| 样本峰值时刻 | `argmax_t count(...)` | 仿真秒 | 样例：10 枚 @ t=1 648.3 |
| 交战强度 | `median_t len(cts)` | 批 | 样例中位数 51，范围 5–64（仅非 null 行） |
| 敌方损失 | 对侧 `own` 的"出现后消失"计数 | 个 | **只能取对侧 `own` 的确数**；本方 `cts` 的消失计数**系统性偏高约 2.2×**（快照：`cts` 近似 47.0 vs `own` 确数 21.75） |
| 段数（重试次数） | `count(i==1)`（同一 ep 内） | — | ≥2 表示该局被重跑过 |

**禁止的派生**（字段不支持，做了就是造假）：单发命中率、交战持续时间、单条指令的因果归因、用本方 `cts` 当敌方损失（只能当"情报可见性衰减"）。

## 7. 已知坑（逐条给出后果与处理）

### 7.1 追加写 + 重试 ⇒ `i`/`t` 会归零

- 现象：样例文件 214 行 = 段1（77 行，t 0→2 247.3）+ 段2（137 行，t 0→4 050.3）。
- 后果：直接按行序画时间序列会出现**时间倒流**（实测出现一次 Δt = −2 247.3 s）。
- 处理：以 `i==1` 为段边界切分；段序号记为 `seg`，主键为 `(tap, side, seg)`（`tap` = `arm__ts`）；只有**最后一段**是有效运行，前面的段由管道计入 `episode_metrics.csv: tap_passes` 并弃用。

### 7.2 失败局不删行

- `runs.ok=false` 的行必须保留，否则失败率无法计算，而失败率**本身可能是臂相关的**（规避动作越频繁的臂越容易踩到 `DropTarget` 类异常；本实验已用 `USE_DROPTARGET=False` 规避，但其他异常路径未穷尽）。
- 分析时：分母用"尝试数"，分子用"`ok=true` 且 `reset==1` 的局数"。

### 7.3 `sim_end` 有两种分布

- 满时长：10 800 s（361 步）；早停：快照实测 3 164.3 s（107 步）/ 4 339.3 s（146 步），样例另有 4 050.3 s（136 步）。
- 快照特征：**早停局 `ok=true`、`winner=1`、`error_side=""`**，且红方大比分领先（638 / 556，满时长局为 1457 / 1363）——“胜负已定后平台提前收局”是目前最符合证据的解释，但机制**未定位**（设计文档 §6.1）。
- 后果：得分速率随早停而抬升（快照 4 局：726 / 461 / 486 / 454 分/h，最高值来自最短那局），**直接拿速率跨臂比较会系统性地奖励“早赢的局”**。
- 处理：主指标用得分速率 + 满时长子集（`sim_end ≥ 10 799`）；`sim_end` 与 `full_length` 必须逐臂报告。

### 7.4 `damage` 在红方 `own` 中恒为 0（蓝方不恒 0）

- 统计：样例（探测局 T1）214 行、25 780 个单元·点，`own[][7]` 最大值 = **0.0**；真实数据快照（4 局）**红方同样全为 0**，而**蓝方 `own` 出现 0–87.5** 的非零值（`analysis/README.md` §3）。
- 原因：红方单元的毁伤过程**不可观测**——单元一旦被击毁就从本方 `own` 消失，没有"部分毁伤"的中间态；蓝方单元有中间态。
- 后果：`red_mean_damage_final` 等**红方毀伤类指标不可引用**；要算"敌方毀伤"，必须用**对侧（蓝方）tap 的 `own`**。
- 处理：已实现管道把这个字段标为不可引用项（`analysis/README.md` §3）；本字典同步此结论，不再把"平均毀伤"当红方指标。

### 7.5 得分是零和，但"分"的来源不止一种

- `red_score + blue_score = 0` 恒成立（样例 269 + (−269)）。
- 但分数的构成包括：摧毁目标双向全额计分、登陆准备区按停留时长累计（+150 可多次）、防御区加固 +250（每区一次）、支援区 +400（一次）、禁航区每 20 s −10。**同一分数可由完全不同的战术路径产生**，因此分数差不能翻译成交换比或命中率差（设计文档 §6.3）。

### 7.6 `wall` 是 epoch 秒，且不覆盖整局

- `wall` 是采样时刻的 Unix 时间戳（UTC+8 本地显示 = `wall` 换算后 +8 h），与 `runs.ts`（本地时间字符串）**不是同一口径**，必须先统一。
- 样例对账：`runs.ts` = 23:50:23；首个采样 `wall` = 23:50:57.88（差 **34.9 s**，与“冷启动+载想定 45 s”同量级；`ts` 的确切写入点【未验证】）；末个采样 = 23:52:03.12（距 `ts` 100.1 s）；`runs.wall_s` = 128.2 s ⇒ 末次采样之后仍有 ≈28 s 的收尾（取结果/写库/退出）。
- 后果：**不能用 `tap.wall` 反推单局墙钟**；它只能用于和智能体日志（`logs/*.log`）对齐到秒级。

### 7.7 `own` 名称不规整

- 同一文件中同时存在 `"TB2 无人机 #15"`（空格）与 `"TB2 无人机#14"`（无空格）。按名称做键会分裂实体。
- 处理：不要用名称连接；同一局内以"位置 + 域 + 计数"做统计即可；跨局比较只用**计数**。
