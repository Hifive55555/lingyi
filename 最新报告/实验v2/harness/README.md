# 实验脚手架与"部署副本 ≠ 仓库副本"的差异说明

> 这一节是给真实性审查用的：论文里跑的实验，用的是**部署副本**；仓库里保存的是**整理后的副本**。两者差异必须写清。

## 1. 目录

| 文件 | 跑在哪 | 作用 |
|---|---|---|
| `pi_v2_run.py` | 靶机 `D:\LingYi\intelligent\ai\` | 单进程 runner：读 job.json、按 `PI_THETA` 把参数打到类属性、逐局跑并落 `runs.jsonl` |
| `pi_v2_drive.py` | 靶机 | 批量驱动：一局一进程、单局超时、失败重试、时间预算、断点续跑 |
| `pi_tap.py` | 靶机（挂红蓝双方） | 只读态势采样器：每决策周期落一行 JSONL（本方单元 + 情报 + 总分） |
| `pi_v2_task.ps1` / `pi_v2_drive.bat` | 靶机 | 用计划任务把 python 投到 Session 1（引擎必须在交互式桌面会话里才能起） |
| `plan_*.json` | 靶机 | 各批次的实验臂定义（θ、局数、预算） |

## 2. 部署副本相对仓库的三处改动

| # | 文件 | 改动 | 为什么 | 是否影响论文 |
|---|---|---|---|---|
| 1 | `Mission_tactics_red.py` | `_best_aam()` 改为扫 `Mounts/Magazines/Loadouts` 三个容器、`WeaponRecs` 兼容 dict/list、射程优先走平台 `query_data.get_weapon_info`、机炮按 10 km 下限剔除 | 原实现只认 dict + sqlite 直连 `model.db`，在平台运行态两者都不成立，导致**空战规则从未开火**（v1 批次 131 局 `fire_aam=0`） | 是。**该修复已合入仓库副本**，v2 批次即修复后数据 |
| 2 | `Mission_tactics_red.py` | `USE_DROPTARGET = False`，规避/召回不再发 `DropTarget` | 平台 Lua `DropTarget` 作用在已退任务/舰载机/刚被毁单元上会抛未捕获异常并带崩整局（实测复现 3 次） | 是。影响面：规避仍生效，只是不主动清空攻击目标 |
| 3 | `Mission_all_red.py` | 增加 `AIR_WRA_NM_OVERRIDE`（把平台"自动开火距离"压到 1 海里） | 只为造出 `wra_nm=1` 实验臂，用来测"没有条令自动开火时规则自己怎么打" | 是。**该开关只存在于部署副本**（仓库副本已按使用者意见回退）；论文 2.5 节把它写成"实验干预"，不是智能体功能 |

> 结论：仓库里的 `Mission_tactics_red.py` 与部署一致（含 #1、#2）；`Mission_all_red.py` 不含 #3，需要复现 `wra_nm` 臂时按本文第 2 表重放这三行改动。
