## 1. 环境与连接（复现前提）

### 1.1 SSH 与编码

```sh
# 已有封装（见仓库根 远端连接Windows主机与截图.md）
~/.cache/pi-ssh/ssh-hifive 'chcp 65001 >nul & hostname'
```

本次新增/沿用的封装（都放 `/tmp`，可复制到仓库 `scripts/`）：

| 文件 | 作用 |
| --- | --- |
| `/tmp/win.sh 'powershell 命令'` | 一条 PowerShell 命令，强制 `[Console]::OutputEncoding=UTF8` |
| `/tmp/win_ps.sh /tmp/x.ps1` | 上传并执行本地 `.ps1`（整文件 base64 落盘再 `-File`） |
| `/tmp/put.sh <本地文件> <远端路径>` | **大文件分块上传**（每块 3000 字符 `AppendAllText`，再 base64 解码落盘） |
| `/tmp/get.sh <远端文件> <本地文件>` | 远端文件 base64 回传到本机 |
| `/tmp/reg2.ps1 -Script <ps1> -Name <任务名>` | 用 **计划任务** 把脚本投递到 Session 1 执行（`-LogonType Interactive -RunLevel Highest`，**用 SID**） |

**坑（都踩过）**

1. 含中文的 `.ps1` 必须存成 **UTF-8 with BOM**，否则 PowerShell 5.1 按 ANSI 读 → 中文全乱、`Find` 找不到元素。
2. `powershell -Command -`（stdin 喂脚本）会**静默截断**，一律落盘 `-File`。
3. 一次 `ssh` 命令行 **上限 ~8 KB**：大于这个长度的 base64 必须分块（`put.sh`）。
4. `$args` 是 PowerShell 自动变量，`$args = @(...)` 赋值无效 → `Start-Process` 拿不到参数（本次就因此白等一轮）。
5. 远端 python 要 `PYTHONIOENCODING=utf-8`，否则日志里中文变 `????`。

### 1.2 会话与权限

- `sshd` 在 **Session 0**（无交互桌面）。`Plat.exe` 是 Qt 程序，**必须在 Session 1** 才能建窗口站/消息队列，否则 `reset=-1`、端口不监听。
- 本次所有 GUI 操作都用计划任务投递到 Session 1（`SessionId=1` 已验证）。
- **但**：计划任务（`RunLevel Highest`）起来的 `APlatformLobby → 单机版启动` 链条，`Plat.exe` 会带一个标题为「错误」的窗口且 21001 不监听；**手动右键“以管理员身份运行”就正常**。→ 差别未定位（怀疑完整性级别/parent token），下次可试 `Start-Process -Verb RunAs` 或 `PsExec -i 1 -s`。

## 2. 脚本化建想定的三条路（按推荐度）

### 2.1 ★ 路线 A：引擎 gRPC `executeLua`（本次主力，已跑通）

**协议事实**（来自 `D:\LingYi\intelligent\ai\proto\ServerInterface.proto`）

```proto
service SimRpc {
  rpc executeLua(RequestExecuteLua) returns (Reply);        // 全 Lua 指令接口
  rpc newScenario(...) / loadScenario(...) / saveScenario(...)
  rpc getScenarioContent(...) / getScenarioBasicInfo(...) / getScenarioList(...)
  rpc addSide(...) / addUnit(...) / setSidePosture(...) / setSimulationStatus(...)
  // …共 244 个 rpc
}
message RequestExecuteLua { string script = 1; }
message Reply { int32 code = 1; bytes result = 2; }
```

**TLS 问题（关键坑）**：同一个 21001 端口，两种形态都实测到过：

| 引擎由谁启动 | 传输 | 表现 |
| --- | --- | --- |
| **客户端**（APlatform/管理员） | **TLS + HTTP/2**，自签证书 `CN=MyCA`，ALPN `h2` | 明文 grpc 连上去 → `End of TCP stream` |
| **python 框架**（`GameConnectLocal.create_engine`） | **明文 h2c** | 明文可直连；TLS 握手 → `WRONG_VERSION_NUMBER` |

客户端引擎的 TLS 直连要点（我实现了两个版本）：

- 本机 Linux（Python 3.12 + `grpcio`/`h2`）：
  - 取服务端证书 → `grpc.ssl_channel_credentials(root_certificates=pem)`
  - **必须**加 `('grpc.ssl_target_name_override','MyCA')`，否则 `Hostname Verification Check failed`
  - **必须**加 `('grpc.enable_http_proxy',0)`（本机有 `http_proxy`，grpc 会把它当 CONNECT 代理 → `127.0.0.1:7891`）
  - 或者干脆手写 `TLS + h2`（`ssl` + `h2` 库），**免证书校验**，最稳（脚本 `ly_h2.py`）
- 目标机 Windows（`ray210\python.exe`，有 `grpc 1.62.2` + 现成 pb2）：`engine\LingYi\entitys\gameenvs\common\ServerInterface_pb2*.py` 可直接 import，明文 `insecure_channel` 即可连**明文引擎**（脚本 `pi_lua.py`）。

**验证过的 Lua 序列（空白新建，全跑通）**

```lua
NewScenario('','')                                   -- 返回 0S-…（想定 GUID）
SetScenarioInfo({TITLE='PI脚本建想定-空白演示', STARTTIME='2026-01-01 08:00:00',
                 DURATION=86400, COMPLEXITY=1, DIFFICULTY=1, DESCRIPTION='<base64>'})  -- 返回「设置成功」
AddSide({side='红方'})                                -- 返回推演方 GUID
AddSide({side='蓝方'})
SetSidePosture('<红GUID>','<蓝GUID>','H')              -- 敌对
SetSidePosture('<蓝GUID>','<红GUID>','H')
AddUnit({side='红方', type='SHIP', name='DDG-113 #1', dbid=2866, latitude=25.5279, longitude=153.2545, heading=90})
AddUnit({side='蓝方', type='SHIP', name='CVN-78 #1',  dbid=506,  latitude=26.2,   longitude=151.0,   heading=270})
Command_SaveScen('D:/LingYi/Data/Scenarios/PI-Lua新建-空白演示.scen')   -- 返回 Scenarios/xxx.scen
```

**回读校验（同一台引擎）**

```lua
LoadScenario({PATH='PI-Lua新建-空白演示.scen'})   -- 返回 "OK"   ← 参数必须是 table！
GetScenarioTitle()                               -- PI脚本建想定-空白演示
GetSides()                                       -- "0S-…","红方";"0S-…","蓝方"
GetScenarioContent('PI-Lua新建-空白演示.scen')    -- 返回 decompressed <Scenario> XML
```

**路线 A 的坑**

1. `LoadScenario('xxx.scen')`（**直接传字符串**）→ 引擎抛异常，随后 **RPC 报 `Unexpected error in RPC handling` 并崩溃**。必须 `LoadScenario({PATH='xxx.scen'})`。
2. `GetScenarioContent(name)` 里的 `name` **要带 `.scen`**；不带后缀返回 `加载想定失败`。
3. `SetScenarioInfo` 的 `DESCRIPTION` 是 **Base64**，不是原文。
4. 同一引擎上连续两次 `LoadScenario` 后出现过引擎崩（第二次 `Load` 返回 OK，紧接的 `GetScenarioTitle` 连接重置）。→ 多局/多想定建议一局一进程。
5. 我们起的 python 引擎会和客户端抢 21001；收工前必须清 `Plat.exe`。

### 3.2 UI 自动化的可靠性问题（本次最大时间黑洞）

| 现象 | 说明 |
| --- | --- |
| `root.FindAll(Children, pid)` 偶尔返回 **0 个窗口**、`Descendants` 偶尔返回 0 | Qt 的 UIA/MSAA 桥抖动；**重试 5~10 秒通常恢复**（`diag.ps1` 里 520 个元素、`st2` 里 516 个都是正常值） |
| 客户端以管理员运行时更不稳 | 怀疑 UIPI（低完整性脚本操作高完整性窗口）；用 `RunLevel Highest` 计划任务有时能读、有时读不到 |
| 菜单项是 CheckBox | `InvokePattern` 有时不触发；**按坐标点击**（`SetCursorPos` + `mouse_event`）更可靠，但要先 `SetForegroundWindow` |
| 弹窗 | 失焦即关；脚本结束（计划任务进程退出）也会关 |

**结论**：UI 自动化“能做但不值得依赖”。**人手点 4 下 = 30 秒**，脚本调试一轮 = 5 分钟起。建议：UI 侧固定由人操作，脚本只做**验证/取数/截图**。

### 3.3 智能体是怎么“跑起来”的（实测进程真相）
